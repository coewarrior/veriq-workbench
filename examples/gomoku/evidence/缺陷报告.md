## BUG-001 非法或异常 `SSID` 可导致服务端进程直接崩溃

### 1. 缺陷基本信息

| 项目 | 内容 |
|---|---|
| 缺陷编号 | `BUG-001` |
| 缺陷标题 | 非法或异常 `SSID` 可导致服务端进程直接崩溃 |
| 所属模块 | `/info` |
| 严重级别 | 致命 |
| 当前状态 | 已确认 |

### 2. 复现前提

- 服务端已启动并可正常访问
- 调用 `GET /info`
- 请求头 `Cookie` 中传入非法或异常 `SSID`

### 3. 复现数据

- `SSID=99999999`
- `SSID=9999999999`
- `SSID=9999999999999999`

### 4. 复现步骤

1. 启动服务
2. 调用 `GET /info`
3. 在请求头中传入上述异常 `SSID`
4. 观察接口响应与服务端进程状态

### 5. 预期结果

- 服务端返回 `400`
- 响应体为合法 JSON
- 返回“登录过期”或“Cookie 非法”等业务错误信息
- 服务端进程保持正常运行

### 6. 实际结果

- 服务端抛出 `std::invalid_argument`
- `stoi` 异常未被处理
- 服务端进程直接退出
- 客户端随后只能收到空 `502`

### 7. 相关日志

```text
[2026-07-01 13-21-19 session.hpp-67] 99999999会话不存在！
terminate called after throwing an instance of 'std::invalid_argument'
  what():  stoi
Aborted
```

### 8. 影响范围

- 信息接口非法 Cookie 校验
- 服务整体可用性
- 自动化测试稳定性

### 9. 初步分析

- 服务端在识别到“会话不存在”后，后续代码仍继续执行
- 异常字符串继续进入 `stoi`
- 异常没有被捕获，最终导致进程退出

### 10. 修复建议

- 对 `SSID` 做判空、格式、范围校验
- 对 `stoi` 增加异常处理
- 一旦 `SSID` 非法或会话不存在，立即返回错误响应并终止后续逻辑

## BUG-002 服务进程崩溃后，对外持续返回空 `502` 响应

### 1. 缺陷基本信息

| 项目 | 内容 |
|---|---|
| 缺陷编号 | `BUG-002` |
| 缺陷标题 | 服务进程崩溃后，对外持续返回空 `502` 响应 |
| 所属模块 | 网关/接口服务 |
| 严重级别 | 严重 |
| 当前状态 | 已确认 |

### 2. 触发背景

- 在 `BUG-001` 等崩服场景触发后，服务端进程退出
- 服务退出后，后续接口访问不再返回正常业务 JSON

### 3. 预期结果

- 即使个别请求异常，服务也不应整体退出
- 失败请求应返回明确状态码和错误信息
- 单个异常输入不应导致全站接口不可用

### 4. 实际结果

- 服务端崩溃后，接口持续返回空 `502`
- 自动化脚本只能拿到空响应体
- `response.json()` 无法解析

### 5. 典型现象

- `/reg`、`/login`、`/info` 都可能被连带影响
- 测试结果会被环境崩溃整体污染

### 6. 影响范围

- 接口联调
- 自动化测试执行
- 服务可用性验证

### 7. 修复建议

- 优先修复会导致进程退出的根因缺陷
- 在服务层增加统一异常保护
- 增加更清晰的服务端错误日志，快速区分业务失败和服务已崩

## BUG-003 登录建会话后，特定信息访问场景仍可触发 `stoi` 异常并导致服务崩溃

### 1. 缺陷基本信息

| 项目 | 内容 |
|---|---|
| 缺陷编号 | `BUG-003` |
| 缺陷标题 | 登录建会话后，特定信息访问场景仍可触发 `stoi` 异常并导致服务崩溃 |
| 所属模块 | `/info` 会话流程 |
| 严重级别 | 致命 |
| 当前状态 | 已确认 |

### 2. 触发背景

- 在继续执行信息接口相关测试时，出现新的服务端崩溃日志
- 本次不是“会话不存在”分支，而是在会话已经创建后依然发生 `stoi` 异常
- 当前最可疑的对应自动化场景为 `TC-INF-011`，即篡改 `SSID` 的越权访问流程

### 3. 复现线索

1. 注册并登录新用户
2. 服务端正常分配 `SSID`
3. 后续信息访问流程继续触发字符串转数字异常
4. 服务端进程退出

### 4. 预期结果

- 登录后应正常创建会话
- 后续信息访问即使出现越权、篡改或非法参数，也应返回业务错误
- 不应导致服务进程退出

### 5. 实际结果

- 服务端已完成会话创建
- 之后仍触发 `std::invalid_argument`
- 进程被 `Aborted`

### 6. 相关日志

```text
[2026-07-01 14-15-06 session.hpp-51] 正在分配新的 SSID: 2, 用户 UID: 373
[2026-07-01 14-15-06 session.hpp-19] 会话创建！
terminate called after throwing an instance of 'std::invalid_argument'
  what():  stoi
Aborted
```

### 7. 影响范围

- `/info` 越权访问场景
- 会话创建后的信息查询链路
- 服务稳定性

### 8. 当前处理

- 对应危险用例已临时停测
- 避免在缺陷未修复前重复打崩服务

### 9. 修复建议

- 排查 `session.hpp` 中会话创建后的后续处理逻辑
- 明确哪些字段进入了 `stoi`
- 对所有外部输入和会话相关字符串增加异常兜底
