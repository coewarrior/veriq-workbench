## v0.7.0 内网交付

团队入口：`http://127.0.0.1:18089/`。网页无需安装，使用说明在 `/guide`。

- 首页「体验完整流程」创建独立资源示例会话，生成用例、发送真实测试请求并保存原有可视化报告；不调用模型。
- 自有文档可在网页继续处理，或保存目标后复制完整消息给 Codex；无需先下载项目源码。
- 交接消息包含当前 origin、会话、目标、一次性连接码和 `/static/agent-guide.md`。新 Codex 使用 `/static/api-test-client.py`（Python 3.9+ 标准库）即刻调用同一套工具；同文件支持标准 MCP stdio，长期注册是可选项。
- `/static/agent-tools.json` 提供全部 27 个工具格式、执行说明和客户端 SHA-256；单测校验与原 MCP 完全一致。
- 每次交接生成新连接码，10 分钟有效。多连接共存；每个工作空间最多 30 个有效授权，可从网页撤销全部。旧版单凭据仍有效。
- 资料保存在服务器并按账号隔离。完整报告 URL 可在内网免登录只读查看；项目、原文、原始 JSON、配置和操作接口仍需登录。

管理员可用 `API_TEST_ALLOWED_ORIGINS` 登记明确允许的内网测试目标，以逗号分隔完整 origin（例 `http://test-api.internal:8080`），只填协议、主机和端口；默认仍仅信任已有示例地址。新增目标需更新服务环境并重启，不向网页用户开放任意内网地址。当前不是企业账号 / SSO 系统。

Codex 需有本机终端权限并能访问内网；不能通过粘贴文字强制加载未配置的 MCP。因此提供免安装调用路径来完成当前任务，注册 MCP 不作为任务关卡。Web 页面不会调用用户未授权的 Codex 账号。模型 API 路径保留为可选项，费用由各自服务商收取。

# Codex 按任务目标执行 · v0.5.0

用户提供文档和目标，Codex 负责推进到最终报告。网页保存资料、显示进度与报告；四个步骤不是必须让用户逐次点击的关卡。

- **完整接口测试**：读取文档 → 按需设计用例 → Codex 自行核对采纳 → 在已授权环境执行 → 查看结果、处理可修正的问题 → 汇总最终报告。
- **只检查文档**：读取原文 → 分析一致性、缺失信息和问题 → 直接发布分析报告。无需用例、状态码断言、测试环境或清理步骤。
- **其他目标**：在任务目标中直接描述。部分检查缺条件时，完成其余工作并在报告中列明缺口，不能把未执行记为通过。

MCP 不调用 DeepSeek 或其他模型 API；推理使用 Codex 自身额度。真实 HTTP 请求仍由服务器执行引擎发出。

## 安装与连接

在源码目录执行（Python 3.11+）：

```sh
python3 -m venv .venv
.venv/bin/pip install -e '.[mcp]'
codex mcp add api-test-workspace -- "$PWD/.venv/bin/api-test-mcp" --url http://127.0.0.1:18089
```

网页左下角「授权 Codex 访问测试台」→「生成连接码」，复制消息给 Codex。授权范围是当前账号下的测试会话与报告，连接本身不选择会话、不开始测试。连接后可直接给 Codex 文档和目标，由它导入并创建新会话；也可在网页导入或打开会话，点击「交给 Codex 完成任务」，复制包含会话编号的消息给 Codex。网页当前选中的会话不会自动传递给 Codex。连接码 10 分钟有效、仅可使用一次；凭据保存于本机 `~/.local/state/api-test-mcp/` 的 0600 文件，服务端只存摘要，180 天失效，可在网页撤销。不要将连接码或凭据提交到 Git。MCP 不读取网页模型 API Key。

新建会话时保存文档、说明任务目标；随后点击「交给 Codex 完成任务」，把消息发给 Codex。任务目标也可在 Codex 对话中补充或修改，最新用户指令优先。已有会话可以直接指定会话 ID。网页自动同步当前会话的结果，无需回网页逐条采纳或推进步骤。

原文即使自动解析失败也会保留供 Codex 检查。仅 HTTP 执行需要符合声明式用例格式；检查结论和建议直接写入报告，不需要伪装成可执行用例。

## MCP 工具

| 工具 | 用途 |
|---|---|
| connect_workspace | 用一次性连接码连接工作空间 |
| get_test_workspace | 会话、模板和已配置环境 |
| list_test_sessions | 按类型读取精简会话和当前工作流状态 |
| start_test_workflow | 从一句目标直接创建 UI/API 会话；仅返回真正缺少的输入 |
| save_test_materials | 补充非敏感目标、规则和测试数据 |
| get_workflow_status | 读取就绪状态、进度、报告、缺陷决策统计和下一步 |
| start_regression_test | 从历史 UI 报告和人工决策建立新回归轮次 |
| get_defect_decisions | 读取拒绝、暂缓、待回归及回归结论 |
| finish_test_workflow | 根据 UI/API 类型调用现有报告发布链路 |
| configure_task | 保存任务目标与环境选择，不发送请求 |
| import_document | 保存原文并尝试解析，可接收不完整或不支持的文档做分析 |
| get_test_document | 分页读取原文、任务目标与解析提示 |
| get_test_context | 需要 HTTP 测试时读取契约、格式、版本、环境能力与阻塞原因 |
| submit_test_cases | 按稳定 ID 分批保存或修正用例 |
| generate_rule_cases | 可选的本地规则生成，替换当前方案，不调用模型 |
| review_test_cases | Codex 在授权范围内自行核对采纳具体用例 |
| execute_tests | 执行真实 HTTP 测试，返回异步任务 ID |
| get_test_job | 读取任务状态，不能因仍在运行而重复提交 |
| publish_task_report | 直接保存分析或任务汇总报告；执行统计只能引用本会话真实运行记录 |
| get_test_report | 获取最新分析或执行报告 |

`publish_task_report` 接受自由文本 summary、sections（title/content）、findings（title/detail/evidence/recommendation/severity）。没有固定检查场景或必填断言。需要说明实际执行时传入保存的 run_ids；服务器从记录计算请求次数，保留完整断言和清理证据。

报告中的失败用例提供“复制接口缺陷描述”，根据冻结用例与本次请求、响应、失败断言整理标题、环境、复现步骤、预期和实际差异。复制正文不包含内部文件路径、运行编号或开发无法访问的附件引用；请求与响应直接包含在正文中。可以在报告内编辑草稿再复制，原始证据不变；内网 HTTP 和离线 HTML 均提供复制回退。执行异常与清理失败分别生成异常描述，未执行用例不生成接口缺陷。仅检查文档时，每项发现提供“复制问题描述”。描述生成不调用模型、不重新执行请求，不推定根因、影响范围或复现次数。

老 Codex 连接若尚未刷新新工具，可读取 `get_test_context.report_submission`：通过既有 `submit_test_cases` 提交单条 `record_type: task_report` 报告记录，便可直接出报告。原文也可从 contract.sources 的 document 摘录读取。无需中断已连接的工作空间。重新打开 MCP 连接后会提供最新完整工具集。

## 真实测试的边界

执行器保留请求、鉴权、断言与清理的有效性校验，不能伪造预期、任意执行代码或调用未授权的目标。需要资料时，Codex 先检查现有上下文；确实缺少目标地址、凭据或业务规则时才询问。文档分析不会受这些执行前置条件阻挡。

当前声明式引擎每次提交最多 40 个用例、每文档执行契约最多 200 个接口，每用例最多 12 个业务步骤。大型任务分批处理，不能因为格式或某个接口的限制而不给出已完成检查的报告。报告区保留最近 30 份分析报告及 30 份运行记录。历史执行快照不随用例修正而覆盖。

完整报告 URL 是内网只读分享链接，无需登录即可查看 HTML 报告。项目、原文、原始 JSON、配置和所有提交操作继续使用账号或 Codex 授权。网页服务部署于 `192.0.2.20:18089`，无需额外开放 MCP 公网端口。
