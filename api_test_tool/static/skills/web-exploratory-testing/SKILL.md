# 网页探索与深度测试：角色入口

## Codex 判断，平台记录

业务结果、证据是否充分、用例通过或失败、前置条件影响及清理结论由 Codex 结合本轮目标、资料和真实观察判断，并显式提交。平台如实保存和展示，不按关键词、描述枚举、固定上传通道、文件名在文案中的出现或引文精确匹配拒存拒发，也不从检查点自动重判父用例。父用例的 status、actual、conclusion、ai_analysis 由 Codex 保存；record_test_checkpoint 只更新指定检查点。

依赖台账和 checkpoint gaps 是供 Codex 判断的诊断，不覆盖已保存结果，也不据此阻断资源候选。明确 work_unit.depends_on 保留阶段顺序，以前置阶段已完成（passed 或 failed）为依据，不要求业务通过；Codex 仍按实际条件决定下一步。完整范围、持续探索、独立用例、证据核对和交付自查继续执行，不把自查变成平台门槛。

平台继续保护真实身份、账号及资源归属、引用关系、数据结构、CAS 修订、用户范围和真实退出。pending/unknown 保存须核对原回执且不重放；明确 rejected/not_sent 仅记录该次保存失败，不阻止发布当前已保存版本，也不代表失败内容已保存。清理描述原样保留；原操作的 business_completed 与 original_operation_resolved 决定结算，未清理不等于继续占号，未知实际操作及明确保留现场仍按原保护处理。

## 当前平台全局范围（2026-10-26）

当前平台全局范围：多账号、双账号、跨账号及跨租户对照/隔离业务场景一律不测（用户明确排除多账号场景）。保留具体设计和已有真实结果；未执行项使用 not_run，not_run_reason 填写上述原因；UI cases.account_scope、API design.account_scope 使用 multi_account/cross_account/cross_tenant 明确范围。不算通过，不申请第二账号、不等待账号集合、不为其创建执行会话或续接，不另做替代测试。普通继续测试/重测不解除此规则。不同模块各用一个账号并发仍允许；单账号权限、匿名及其他适用风险覆盖保持。已有真实对象责任的必要清理和无需账号的报告仍按原授权及回收协议处理，不扩展业务测试。

此明确范围变更优先于下文历史多账号示例；既有隔离、授权、清理及回收协议仍保护历史现场，不授权发起新多账号业务。


以本轮 `get_test_document` / `get_test_context` 返回的平台随包版本为准，不以本机同名旧 Skill 替代。目标、完整相关附件、明确模型配置、执行权限、现场保留和本轮范围沿原任务传递；资料不是额外授权。角色只分配职责，不改变工具权限。

| 返回角色 | 当前只读的职责参考 | 本轮工作 |
| --- | --- | --- |
| `coordinator` | [协调者](references/coordinator.md) | 登记完整模块树、各独立聊天和任务包，处理真实交接异常及范围偏差，汇总 |
| `worker` | [模块执行者](references/worker.md) | 本模块探索、具体设计、执行、逐条保存和真实交还 |
| `single` | [完整单模块执行](references/worker.md) | 保留完整原执行流程，不要求另起协调聊天 |

显式 role 优先；未传角色时已知模块记录返回 worker，其他旧调用返回 single。网页复制任务消息明确 coordinator；dispatch 为每个模块返回独立 worker_packet，不能把协调全包交给工作者。完整覆盖、持续探索、独立结果、未知操作核实、权限、S1 和报告真实性在角色参考中继续有效。

独立状态/输入/边界分别保存 case_id；收尾按 [覆盖设计](references/coverage-design.md) 在现有 review_notes 留下原始范围逐项核对，不能以计数代替。授权、人工步骤、规则、依赖和工具故障分别记录；浏览器工具中断沿 [原环境恢复](references/direct-isolated-browser.md) 留凭据并恢复，不把超时当业务失败或已证明无法恢复。

Codex 直接执行的多模块新独立测试（含明确新回归），首次派发使用本轮新建的协调聊天和各模块独立聊天；当前聊天已为本轮新建时直接协调，不递归另建。同轮续测、恢复或重复复制同一 MCP 消息沿本轮真实绑定和检查点继续，不重复创建执行者；跨 task_id 的同轮来源按 [协调者](references/coordinator.md) 追溯。worker 使用 assignment 已绑定的本轮聊天，不自行再建聊天；single 不另增协调角色。
