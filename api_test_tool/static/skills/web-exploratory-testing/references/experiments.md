# 质量与耗时对照实验

仅在用户要求比较模型、推理强度或执行策略时使用。目标是判断哪种方法在保留有效验证的同时更省时间，不按用例数或报告长度选胜者。

## 分开回答两个问题

- **探索质量**：给各组相同目标、资料、账号能力和工具条件，独立侦察、设计并执行。保存新发现，比较实际验证的功能/规则、可复现缺陷、误报和遗漏。首版仍可增量补充，不为可比性锁死探索范围。
- **执行效率**：从已核对的具体设计建立相同基线，各组独立执行相同输入、步骤、必要观察和判定。可比较逐条工具调用与批量调用；批量内部每条独立留结果，异常返回判断，不能合并判定或删掉恢复/清理。明确已知页面的复测与首次探索不同。

两种问题可分轮进行。先确认浏览器通道、目标地址和账号初态可用，区分冷启动、侦察与稳定执行。模型组遇到不同账号权限、工具中断或业务版本时保留结果，但注明该轮有混杂因素，不将差异全归因于模型。

模型名称和推理强度分别记录配置值与来源。标题或派单只证明请求配置；只有实际运行元数据可支持已核实。无法取得模型身份、Token 或工具调用数时保留未知，不用任务标题推导真实型号或编造用量。并行实验只有在已获委派授权且资源隔离成立时开展。

## 测量边界

记录实际可得事件：任务开始、浏览器/账号就绪、首次基线保存、正式执行开始、执行结束、报告完成。准备、执行、证据整理和发布窗口分开解释；平台现有“首次保存用例至报告发布”不能代表包含前置工作的总耗时。项目最后更新时间可能来自事后补充，不作为原实验结束时间。

新平台支持用 `save_ui_test_cases` 的可选 `experiment` 保存本轮实验记录；字段和客户端透传方式以当前工具清单为准。事件发生后再写时间，不能事先填结束时间。未取得字段省略，服务端的保存/发布时间与执行端自报时间区分展示。此记录辅助复核，不改变用例状态或形成发布门槛。

同一已知页面可交错执行不同策略，复测观察是否一致，并说明顺序、缓存及熟悉度的影响。工具内部动作时间与整个流程墙钟分别记录；工具调用之间的间隔包含调度、通信和模型判断，不能直接叫作后端响应时间或模型纯思考时间。小样本报告实际数值和限制，不外推整个平台或复杂业务同幅度提速。

## 质量与停止依据

比较以下可核验结果，按本轮目标选择有用指标，不自动合成一个质量分数：

- 已独立核验的关键规则与最终业务结果；部分验证保留未完成部分。
- 缺陷独立复现及证据；相同触发条件和影响的重复记录先归并，区分误报、待确认规则和工具问题。
- 设计中具备条件但未执行的遗漏，以及真实共同阻塞的影响范围。
- 数据、截图、报告可读性与本轮资源清理的实际结果。

历史预检记录、正式业务用例、只补充说明的报告分别计数，不重复统计同一实验。继续实验应能消除重要不确定性、复核差异或验证改进；相同条件下继续只产生已知工具失败时，按既有失败停止与恢复约定收尾。不要为了增加样本反复触发昂贵或不可逆操作，也不因达到某个用例数量就宣称覆盖完整。
