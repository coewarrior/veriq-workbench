# 固定目标标签，避免前台干扰
## 当前平台全局范围（2026-10-26）

当前平台全局范围：多账号、双账号、跨账号及跨租户对照/隔离业务场景一律不测（用户明确排除多账号场景）。保留具体设计和已有真实结果；未执行项使用 not_run，not_run_reason 填写上述原因；UI cases.account_scope、API design.account_scope 使用 multi_account/cross_account/cross_tenant 明确范围。不算通过，不申请第二账号、不等待账号集合、不为其创建执行会话或续接，不另做替代测试。普通继续测试/重测不解除此规则。不同模块各用一个账号并发仍允许；单账号权限、匿名及其他适用风险覆盖保持。已有真实对象责任的必要清理和无需账号的报告仍按原授权及回收协议处理，不扩展业务测试。

此明确范围变更优先于下文历史多账号示例；既有隔离、授权、清理及回收协议仍保护历史现场，不授权发起新多账号业务。


默认执行路线是 [原生 Codex 执行](native-codex.md)：现有桌面 Codex 默认使用 [直接独立环境](direct-isolated-browser.md) 的 node_repl/Playwright，旧在途保留原工具。平台不转发浏览器动作，保留原生命周期；本页后半部分的旧 browser-session/helper 和 Runner 通道仅供原任务兼容或用户明确选用，不能自动加入默认路径。

新任务默认直接独立环境并自动发现本机依赖；仅旧共享在途新建页面调用 `cua.createBrowserTab('iab', url, {visible:false})`，不能省略 `visible:false` 或在失败时自动切到可见 Chrome。已有明确目标和旧在途任务保持原归属；不为采用新默认迁移它们。隐藏不等于登录隔离，多账号仍须取得真实独立上下文，不抢用、退出或覆盖其他任务的登录态。

执行前检查浏览器工具是否支持按标签 ID 或页面句柄操作。优先复用已有登录态，按用户指定的标签或目标网址核对页面并绑定明确的对象；后续读取、定位、点击、输入、等待和截图都使用同一对象。用户切换 Chrome 前台标签不改变测试对象，不为继续测试反复切回前台，也不在每一步重新获取“当前标签”。按工具实际文档操作，不假定应用级坐标控制具备标签绑定能力。

浏览器名称、别名与数字 ID 可能因执行会话而不同，主代理的 ID 不能直接交给另一个会话使用。别名返回不可用时，先按当前工具的库存接口核对实际类型和 ID，再选择其中支持所需操作的浏览器；不能把一次别名查找失败当成所有浏览器不可用，也不靠猜 ID 连续重试。切换通道后核对登录初态：新标签可能继承用户登录，匿名实验不能通过退出用户账号来制造初态。浏览器级视口等共享设置会影响其他标签，独立实验需核实作用范围。

可访问树和 DOM 定位器可能给同一控件显示不同角色。使用 DOM/Playwright 定位器时，以该通道的实际 DOM 快照为准；已看见控件但角色定位无匹配时，读取对应区域确认角色或名称，再修正定位，不把定位器错误判成产品故障。修正后复用稳定定位器，未知分支才重新侦察。

固定标签与数据隔离是两件事。用户也在操作同一标签时，创建本轮专用测试标签；需要隔离登录、缓存或账号时，使用独立浏览器上下文。不同标签仍可能共享 Cookie、登录态和服务端数据，不能仅凭标签不同就并发修改同一业务状态。独立上下文不自动继承登录态，不擅自提取用户 Cookie。

导航后核对目标页面与当前测试流程的关系。流程打开新标签或弹窗时绑定并记录新对象；原标签关闭、句柄失效或控制连接重建时，依据已记录的目标重新定位或创建本轮测试标签，不能退回操作用户当前前台标签。截图和等待条件也必须属于实际执行该步骤的目标页面。

已知的操作、对应业务的真实完成等待和局部断言在同一次工具调用完成，读取必要区域和结果摘要；全页可访问树用于首次侦察、真实结构变化或具体异常，不随每次点击、输入及用例保存重复读取。仅使用当前原生工具公开允许的 API，不为导入记录 helper 在受限 `cua` 中访问本地文件、凭据、任意网络或浏览器内部状态。控制工具已明确报告锁屏且自动恢复失败时，立即按 execution-optimization.md 保存并交付阶段结果；不要反复请求窗口树或自动解锁。前台被其他任务占用时只尝试一次可用的绑定/隔离通道，仍不能可靠操作就停止对应分支，不通过反复抢切标签继续。

文件上传先尝试绑定标签的文件输入能力；该能力受限时，优先使用支持文件输入的独立上下文，并核对实际上传结果。系统文件选择框、浏览器权限弹窗和应用级键鼠操作仍会占用前台，不能靠绑定标签消除冲突。只有用户已经允许前台操作、目标窗口归属明确且没有其他使用者时才使用这些能力；否则使用可用的独立执行通道，仍无法完成时如实记录对应步骤的条件缺口并继续其他场景，不反复抢占用户窗口。

绑定标签支持文件选择事件时，按工具文档先监听事件再触发控件。直接点击文件输入未产生事件，先核对没有发生上传；页面存在已确认关联的可见上传按钮时，可通过该按钮触发同一标签的文件选择，不凭一次定位或事件超时就断言整个通道不可用。同一通道的多次尝试合并记入一条 `upload_attempts.detail`，保留先失败、后成功的实际顺序与依据，不能丢弃失败记录或伪称使用了其他通道。

本轮记录目标标签、新增页面、上下文和驱动的归属。收尾按现场保留设置停止控制并核实自己创建的资源；绑定用户已有标签不代表获得关闭该标签或退出用户浏览器的权限。

## 旧独立 Playwright 路线的兼容入口

确需独立上下文且执行工具允许本机浏览器时，复用随包 `scripts/browser-session.cjs` 和 `scripts/execution-guard.cjs`，不每轮另写stdin、调试器或HTTP控制服务。已有绑定浏览器工具仍按它的工具文档使用，不替换用户指定的浏览器。使用bootstrap已核实的runtime.json（module/channel），不重复安装环境。

```sh
node browser-session.cjs serve /本组目录/private-session /本组目录/runtime.json
node browser-session.cjs status /本组目录/private-session
node browser-session.cjs run /本组目录/private-session step-001 /本组目录/step.js
node browser-session.cjs result /本组目录/private-session step-001 /本组目录/result.json
node browser-session.cjs close /本组目录/private-session
```

`serve` 在执行工具的长期进程会话内运行，等待ready后用status确认通道；不依赖stdin、无需tty，不以浏览器进程存在代替就绪。私有目录必须尚不存在；只监听随机本机端口，每组独立认证和浏览器上下文。不输出session.json，不读取其他组文件。close只关闭本服务的浏览器，运行中步骤会拒绝关闭；成功后留下closed.json，不清理业务数据。业务清理仍按本轮现场和对象归属执行。

step.js是异步函数体，可用 `s.page/context/browser`、`s.data`、`s.fs/path` 和 `s.actAndWait`，只执行授权流程。run返回步骤ID与接受状态；同ID的result间隔查询，结果写入0600文件，终端只输出状态。同ID/同脚本不重复执行，不同脚本不能复用ID；断线或uncertain先核对实际状态，不能换ID自动重放。会话内步骤串行，独立场景仍可按原规则使用不同会话。及时保存真实观察和已创建对象清单，不以内存作唯一记录。

点击和响应等待从创建时就接上错误处理，避免先启动等待、等点击结束后才捕获等待异常：

```js
const response = await s.actAndWait(
  () => s.page.waitForResponse(r => r.url() === expectedUrl && r.request().method() === 'POST', {timeout: 20000}),
  () => s.page.getByRole('button', {name: expectedButton, exact: true}).click({timeout: 15000})
);
return {status: response.status()}; // 后续继续实际业务断言，HTTP成功不是用例通过。
```

回调均设有限超时；helper等待两者结束再抛错，不重试、不吞异常。其他异步任务也必须及时await/catch。原有控制故障恢复次数和阶段交付规则不变。恢复本组已授权登录可按原授权重新读取本组私有凭据，不额外添加“只能读取一次”限制；凭据不进入步骤结果、日志或报告，结束后按原规则清理。


仅旧独立 Playwright 并行任务按 platform.md 的资源协调约定一次占用整段所需的 account/tab 资源；该旧路线使用原生输入时还需 native:<主机>，未获得占用不能切焦点或执行操作。默认直接执行路线沿已分配账号和绑定的隔离页面执行，不接入旧 helper 锁、不重复 `coordinate_ui_resources`，不在每个动作前新增占用请求。不同窗口仍不隔离全局键盘和文件框，原生工具的前台操作遵守本页已有目标归属与前台约定。只控制本任务明确绑定的页面，结束前确保没有本任务操作在途。


## 旧 Runner 租约中的辅助浏览器

`context.execution_host.provider=platform` 时，浏览器由服务器提供，使用该租约的 `browser` 工具；上传使用已授权 `asset_id` 或真实文件内容。模型所在电脑的路径与辅助浏览器不属于服务器租约，`auxiliary_channels=false` 时不要启动本机 helper 或要求用户安装、配对执行机。文件输入仍实际操作目标页面，不改为直调业务接口；必要场景、覆盖和上传失败的真实记录规则保留。

使用平台账号的独立 helper 必须和 `lease-channel.cjs` 一起使用，在原 runtime.json 增加 `lease_binding: {url: 测试台origin, holder_id: 原执行者, lease_id: 原租约}`；凭据沿用本机私有连接文件，不能把 token 放进 runtime 或命令行。serve 的私有目录使用绝对路径，必须与原浏览器执行连接位于同一机器。ready=false 表示等待原执行机核对进程归属，不能开始操作；helper 自动登记、维护通道心跳、接收撤权并关闭浏览器，不需要模型逐步轮询。实际批次开始和结束才更新业务进展，空心跳不防止无进展超时。

平台停止或通道失联后关闭整组 helper；原执行机按 PID、创建时间、私有绑定和子进程清单确认退出后才归还账号。未知批次保留原 job ID 和核实依据，不重放。普通 close 与停止信号都保存 lease-return.json，回执丢失只重传退出。共享探索仍用平台已有本地请求策略约束的浏览器；未核验分支申请独占后再使用辅助 helper，不能开不受控浏览器绕过共享边界。无平台租约的旧独立测试方式继续有效。
