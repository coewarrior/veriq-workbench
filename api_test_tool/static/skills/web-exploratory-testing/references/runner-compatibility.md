# 旧 Runner 共享探索兼容

仅显式旧 Runner 任务使用；默认原生路线跳过本文件。

**旧 Runner 路线的共享探索兼容说明（不作为默认原生浏览器的开测步骤）：** 共享探索由平台自动接入实时服务，用户只配置项目账号，不填写规则、会话兼容标记或选择器。遵循 `context.exploration_guidance`：有已审阅适配时复用；否则 `exploration_bootstrap=true` 的首成员先正常登录，在页面就绪后从 `navigation_links` 选择 `context.exploration_modules` 对应的本轮实际入口，调用 `prepare_exploration`（当前聊天为 `browser_action=prepare_exploration`，后台为 browser 的 action），传 `parameters={entry_urls:[实际URL,...]}`。没有直接链接的入口先在原浏览器正常打开，使用已观察地址。平台在独占账号下自动核验真实页面、请求和并行会话，生成本批次请求规则；执行者不自行提交规则批准共享，不要求用户进行技术配置。此自动核验接受用户已确认的剩余副作用误判风险，不作为业务用例通过证据。共享成员的登录态由平台按批次注入独立浏览器，直接导航到 `shared_policy.entry_urls` 对应模块，不重复登录或导出 Cookie。已审阅适配的 independent_login 沿原正常登录方式执行。准备只在用户已启动的任务中进行；停止或禁止业务测试时不得运行。`continue_exploration=true` 的回执保留真实快照和待独占分支，继续其他可共享探索和设计；未完成的分支不记失败或通过。共享探索设计完成后在真实阶段边界用原 `request_resources` 转独占；仍需独占才能继续探索时用 `exclusive_exploration=true`，保留持续探索、增量补充和逐条判定。普通独占账号保持连续执行，平台负责会话和资源交接，不增加用户设置或逐步远程核验。 默认原生路线不调用 prepare_exploration，不导出/注入 Cookie，也不把未经验证的原生浏览器说成已受 Runner 请求策略保护；用户已允许原生探索共享账号、由 Skill 约束并接受无逐请求拦截风险；共享成员在需要写入或进入执行阶段时申请独占，账号共享与转独占以平台实际分配为准，不在每个动作前请求平台。


## 原工具传输兼容说明

The following headless-host/browser receipt and helper instructions apply only to existing local_browser tasks; do not apply them to native_browser. Execute in the connected Codex or its independent module chat. For multiple modules the coordinator creates or resumes one visible Codex chat per module (create_thread), never groups modules into subagents; persist its actual thread_id as executor_ref. Subagent slot limits are not module concurrency limits. Missing chat-creation capability is reported separately from account/browser waiting. dispatch uses arguments.modules=[{node_id,dispatch_id,holder_id,executor_ref}] and a stable request_id to persist coordinator offers before spawning. For unavailable executor slots register {node_id,dispatch_id,state:waiting_capacity,reason}. Workers claim the same dispatch_id; expired offers require coordinator reconciliation before reoffering the same node. channel is reserved for the bundled lease-bound auxiliary browser helper, using arguments.event register/heartbeat/closed. Helper startup must include runtime.lease_binding={url,holder_id,lease_id}; shared exploration stays in the policy-enforced browser. Keep a stable unique holder_id per worker, not shared by all workers in a chat. For multiple named modules first register modules through start_session_test, then create or resume one independent Codex chat for each returned leaf with exact node_id; do not ask the user to create the chats manually. The coordinator does not claim an account. claim(task_id[,node_id,account_ids,locks]) atomically requests the complete phase resource set and joins the SAME account queue and returns lease_id when assigned, browser_ready=true/next_action=context after host ACK; it never starts another Codex. While queued with lease_id=null, return/end the worker turn immediately, stop claim loops and self-wakeups, and retain resource_wait.resume_arguments for the coordinator to wake the original chat only when resources are available; action=wait is NOT queue waiting and requires a leased browser for human action; do not call browser/credentials or busy-poll models. context without lease_id plus task_id/node_id returns queue status, not a lost-lease error. context with lease_id reads assigned account metadata, task/Skill and original evidence; credentials retrieves only the leased account for login (never print secrets). browser uses lease_id, browser_action, parameters and stable request_id. Default for known cases when execution_host.case_execution=true: browser_action=batch, parameters={plan_id:stable_id,cases:[{case_id:original_id,steps:[{id,action,parameters}],checkpoints:{original_checkpoint_id:[check_step_id]}}]}. The Runner executes and saves each case before the next, returns actual case/save timings, preserves unplanned checkpoints, and stops the plan on unknown operations or failed saves without automatic model retries. This is not an assertion generator; use explicit observed selectors and expected values. Do not call save again for state=saved. Same plan_id reuses operation IDs on continuation. When context.execution_host.browser_batch=true, browser_action=batch accepts parameters.steps=[{id,action,parameters}] for an already-known ordered chain, reusing existing user permission and retaining separate durable step receipts and lease fencing; failure stops later steps. check uses selector plus expect (visible/enabled/text/value/count); wait for expected state before checking. Intermediate action responses may use response=summary, with a complete final observation; snapshot_selector limits only the requested observation, not test scope. Keep every case, assertion and evidence. Updated clients expose execution_client.browser_batch=true and automatically sequence batch steps on older hosts without restarting their browsers. This compatible transport retains full per-step receipts in a private local journal; result/resume_arguments continues the original batch, never replays an uncertain submission. Native check/snapshot_selector still require execution_host.browser_batch=true; on older hosts retain explicit observations and original assertions, never omit them to fit a batch. Keep the original client credential file and journal when continuing. The tool submits once and waits internally for the same receipt (default wait_seconds=45, 0 returns immediately, up to 50 seconds per call). Only an allocated claim waits for browser_ready; an unallocated claim returns resource_wait.end_turn=true without polling. finish waits for confirmed account release the same way. Read the returned snapshot/result directly; do not generate separate result files and model polling turns for each action. If client_wait.pending=true, use client_wait.resume_arguments to continue the SAME receipt; poll_error describes a transport problem, not a business failure. Unknown receipts stop waiting immediately and are never retried as business writes. client_wait reports actual elapsed_seconds and http_calls; it does not claim test coverage or speedup. Use browser_action=wait with an observed selector/state for an expected page change rather than model sleep/snapshot loops. For browser and credentials, omitted account_id uses the single account already assigned to this lease; with multiple accounts specify the intended context.accounts[].id. Never use an account from another lease; result with that SAME ID reads the durable receipt even after release. Never repeat an unknown business write: inspect via snapshot, then reconcile(operation_id,operation_state=confirmed|not_sent,reason=actual evidence). record proxies record/cases/assets/publish/reference/requirements/save_requirements/dependency/fixture. shared_policy cannot be approved by an executing worker; use the broker preparation flow. claim automatically records receipt with optional executor_ref/coordinator_ref/dispatch_id (actual identifiers, never invented); the installed client fills a known CODEX_THREAD_ID without another request. browser_ready means only browser readiness; business_started is recorded from completed commands. Pending control receipts remain visible until the executor acknowledges its stop through the existing finish call. For overflow exploration, only a verified session-compatible policy permits shared leases; do not label GET requests safe by assumption. The platform automatically prepares live exploration for every configured project. A reviewed adapter may be reused; otherwise the exclusive bootstrap worker logs in normally, selects the actual navigation_links for context.exploration_modules, and calls browser_action=prepare_exploration with parameters.entry_urls. The broker verifies live views, requests and session compatibility and generates the batch rules; the worker cannot approve its own policy. Empirical verification has user-accepted residual side-effect uncertainty and is not a business test pass. Shared workers receive a batch-scoped session in an independent browser and navigate to the matching shared_policy.entry_urls without logging in again. Follow context.exploration_guidance, including exploration_bootstrap. Users configure only project accounts, never internal policy JSON. continue_exploration=true preserves a blocked branch while other verified exploration continues; it is not a business pass or failure. When the shared exploration/design is complete, call request_resources(next_phase=execution,checkpoint[,requirements,account_ids,locks]); if further exploration itself needs exclusivity, use exclusive_exploration=true instead. Use this once at the real stage boundary; never replay the blocked business write blindly. The returned resource result states whether the same context continues or waits in the original queue. Ordinary exclusive testing adds no such handoff or duplicate check. Fixture uses the existing shared-precondition consumer lifecycle, never delete another task's prerequisites. checkpoint saves progress. wait(reason) preserves the browser for human action; send the question to the coordinator for the user in this chat; continue resumes after their answer. If queued without lease_id, finish(task_id,node_id,outcome=blocked,reason) still finalizes unverified work. With a lease, finish(outcome=completed|blocked|yield,reason[,children]) stops the browser and returns the account after confirmed exit, publishes a truthful final including unverified cases. Task status shows actual settlement. Read reported timeouts; caller polling is not business progress. Existing task scope, exploration, incremental design, history, evidence and cleanup rules remain unchanged.
