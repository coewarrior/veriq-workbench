# 人工操作与原现场续测

待操作必须能让接手者找到真实现场。遇到扫码、登录或其他人工步骤时先持久化，再暂停依赖该步骤的链路；独立用例继续。不要只写“请扫码”“请登录”或把产品首页当作操作入口。

在用例或暂停的 checkpoint 中保存 `action_context`，字段都是文本：

- `page_url`：已观察到的实际操作页 HTTP(S) 链接，可包含普通业务对象 ID，不含密码、Token、Cookie、临时授权码或签名。
- `page_title`、`browser`、`tab_id`：当前工具实际提供的页面标题、浏览器及标签标识；未知值留空，不能猜。
- `step`、`object`：停在哪一步，操作的是哪个原订单、岗位、对话等对象。已有 checkpoint 的 correlation 继续保留业务关联。
- `success_condition`：人工操作成功后应在哪看到什么，例如原登录页变为已登录、原订单显示支付成功；不把点击“已完成”本身当成功证据。
- `resume_hint`：如何回到原对象、页面失效时如何恢复，以及下一步检查什么。链接不可分享或含敏感会话信息时，保留原标签及安全到达路径，不把凭据写进报告。

没有 checkpoint 的用例仍用 `pending_action`、`action_type=manual_step`、`action_required` 保存人工动作。有 checkpoint 时将对应步骤标为 pending_action 并保存 action_required/action_context；已完成的前序结果和关联不清空。平台在验证未完成用例上也展示待操作入口，不把验证未完成改成全部通过。

在人工动作完成前保留必要的原标签、临时浏览器上下文、会话及业务对象，不因普通收尾关闭或清理暂停现场。只保留本任务必要资源；用户明确要求结束或清理时遵从。二维码可能过期，不承诺永久有效；过期后在同一对象的原页面刷新，不另建订单或重复付款。

用户完成后优先重新绑定原标签，核对 URL、对象、账号/租户和 success_condition；标签不可用才打开安全链接恢复同一对象。原现场确实无法恢复时说明失效点及恢复动作，不能静默从首页重跑。确认成功后继续暂停步骤和后续依赖检查，前序观察带来源、明确本轮未重复执行；人工完成不直接记为用例通过。

报告先保存操作确认，再统一勾选发起补测，沿用现有 MCP 交接；旧单条续测接口继续兼容。执行端读取 get_test_document 的持久化确认与现场，再用 get_ui_test_cases 读取已准备的继续基线；不生成另一套用例。仍在同一轮执行时，用户完成后核对原现场，通过 record_test_checkpoint 或批量保存真实结果继续即可，不必为了暂停新建报告。新发布轮次保留历史报告。

旧报告缺少现场时如实提示缺口，不根据产品首页或其他测试猜测链接。可从已有真实记录补齐后，用 correct_ui_test_case 的 fields.action_context 保存审计更正，不改原始证据。
