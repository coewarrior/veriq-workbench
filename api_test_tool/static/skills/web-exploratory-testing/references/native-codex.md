# 原生 Codex 执行
## 当前平台全局范围（2026-10-26）

当前平台全局范围：多账号、双账号、跨账号及跨租户对照/隔离业务场景一律不测（用户明确排除多账号场景）。保留具体设计和已有真实结果；未执行项使用 not_run，not_run_reason 填写上述原因；UI cases.account_scope、API design.account_scope 使用 multi_account/cross_account/cross_tenant 明确范围。不算通过，不申请第二账号、不等待账号集合、不为其创建执行会话或续接，不另做替代测试。普通继续测试/重测不解除此规则。不同模块各用一个账号并发仍允许；单账号权限、匿名及其他适用风险覆盖保持。已有真实对象责任的必要清理和无需账号的报告仍按原授权及回收协议处理，不扩展业务测试。

此明确范围变更优先于下文历史多账号示例；既有隔离、授权、清理及回收协议仍保护历史现场，不授权发起新多账号业务。


资源等待遵循 [共同前置与原节点阶段安排](work-stages.md)：先做当前合法可做的原场景，资源边界用完整阶段令牌，真实退出后明确 yield；原用例、覆盖、顺位与未知写入保护保持。

`executor_ref` / `coordinator_ref` 沿平台返回的原标识传递；真实 UUID 与 `thread:UUID` 表示同一聊天。生成器、领取、续接和退出核对接受两种表示，不要为通过本地检查改写 assignment 或创建替代执行者。holder、task、node、dispatch 代际仍须匹配，不同聊天不能互换。

本节是默认原生路径的接口参考。新任务按 [直接独立环境](direct-isolated-browser.md) 在持久 node_repl 中复用真实 Playwright Page；旧在途保留原工具和现场。平台负责账号、资料、结果和 S1 停止，不代理逐个浏览器动作。

普通定位或保存错误保留现场，明确结束才收尾。范围与判定见 [覆盖设计](coverage-design.md)，本模块职责见 [执行者](worker.md)。一次准备后复用绑定和工具说明，不在每条用例前重读本文件。

## 账号与实际登录环境

原生领取在原 `claim.arguments.browser_environment` 提供一次真实环境：`{host_id,browser,context_id,origin,isolation:'shared_profile'|'isolated',evidence}`。固定准备入口可复用 `assignment.browser_environment` 或 `assignment.claim_arguments.browser_environment`；原完整多账号集合使用对应 `browser_environments` 数组，不减少所需账号。标识来自实际工具能力和当前环境；`origin` 是目标的协议、主机和端口。`shared_profile` 在同一 owner、host、browser 和 origin 下只有一份真实登录容量；换 tab、隐藏窗口、独立聊天或 `sessionName` 不增加隔离容量。`isolated` 还须提供同一对象内的 `capability_evidence={source:'public_tool',capability:'isolated_login_context',context_id,reference}`，reference 指向本次实际读取的公开能力依据，context_id 与真实上下文一致，不能自行命名后当作隔离证明。已有在途租约保持原绑定，不迁移现场。

平台按实际账号和环境容量排队。缺环境、环境忙和缺账号是不同等待原因；它们都不等于账号错误，不新增预登录审批。原生 IAB 没有公开独立上下文能力时按共享 profile 的真实容量使用，不伪造 profile，也不无声切到另一后端。领取成功只是资源预留，不能据此称已登录或已确认身份。

取得资源后，在分配的环境中使用本租约账号按原 UI 登录流程登录；不覆盖其他任务或用户正在使用的身份。以实际登录结果在原 `checkpoint.native_login` 保存 `{environment_key,account_id,state:'verified'|'unverified'|'mismatch',method:'assigned_credentials_login'|'visible_identity',evidence,login_succeeded?,expected_identity?,observed_identity?}`；environment_key 和 account_id 使用原回执。使用既有 `checkpoint`，可与首条保存放在一次工具编排中；不增加每步远程检查、额外审批或重复核实回合，不写密码、令牌或 Cookie。

`verified` 仅用于本租约已按分配凭据完成明确的 UI 登录（`method='assigned_credentials_login'`、`login_succeeded:true` 且有真实 evidence），或页面完整同类型身份与平台分配身份确实相等（`method='visible_identity'`，observed_identity 为实际完整值）。成功使用分配凭据登录后，不因页面只显示掩码又阻塞。已有页面只有掩码、手机号与邮箱无法关联时记 `unverified`，不能判 `mismatch`；只有完整、可比的身份确实不同才记不一致，不能用自填 expected_identity 替代平台账号身份。未知身份不冒充已验证，也不把另一个模块的疑问扩散为全部模块失败。真实登录挑战或环境归属冲突沿原人工/资源路径处理，保留具体恢复条件。

原任务恢复使用原 `task_id/node_id/holder_id/dispatch_id` 和原目录。资源通知先经 `native-resume --assignment-file 原文件 --directory 原目录 --notification-file 原通知文件`（周期入口 `input={action:"resume",notification:原通知.claim_arguments}`）机械接入，stage_ready=true 后才准备完整环境并原 prepare --resume；不手抄或遗漏 work_token，也不重复另做阶段预检。已有记录通过 `assignment.resume_record={project_id,execution_id}` 指向本模块原轮。保留全部用例、已保存观察和未决操作，不新建任务、不重建基线、不重放已完成业务。

若网页已先建新的未领取 `session` 占位，需要把既有模块续接到该任务，协调者按 [续测模块登记](platform.md#已有记录的续测模块登记) 使用原节点或 `continuation_modules` 候选中的 `source_node_id` 一次登记；省略 ID 只允许确定来源任务内唯一稳定 key 匹配，不猜标题。成功后使用该任务返回的 `task_id/node_id`、实际派发登记的 `holder_id/dispatch_id` 和独立目录，按 `assignment.resume_record` 恢复原执行记录；不能把旧任务本地绑定或旧派发回执改名当作新绑定。`continuation_source` 保留原 project/execution/case ID、结果、证据及尝试，旧任务仍可查询，旧已退出 holder 不再具有该记录的补写权限。只继续未完成断言和新增授权覆盖，历史通过不重跑、不作为新通过；不复制或重置基线，明确新回归仍走原新轮入口。原任务自身的恢复仍遵守上一段，不因此另建任务或迁移在途执行者。

## 派发到首个页面、观察到保存

已核验普通本地文件读写的 POSIX 原生环境，可在本轮 assignment 增加 `local_observation_stream:true` 与 `local_artifact_io:true`。prepare 在既有工具进程启动只接收本轮观察的客户端，原生浏览器使用静态 `nativeSendObservation` 导出原观察并通过本地命名管道通知；文件事件返回真实保存回执，不经模型转录或另开保存回合。接收程序不操作浏览器、不调用模型、不轮询、不重试业务，仍沿原绑定、租约校验及不可变回执保存。原生工具内不读凭据、不调用平台网络、不动态构造函数。拿到 saved 才继续下一条；响应未知停止并保留原观察，不自动换入口重发。明确结束并真实关页后接收进程退出；保存失败保留原观察和失败回执，pending/unknown 需核实原请求，明确 rejected/not_sent 不阻断当前已保存版本的发布，也不等于实际浏览器已经退出。未核验环境保留原路径，不猜测文件能力。

已核验的选定用例可通过 assignment.browser_call_file 携带完整静态调用供原生工具复用，真实 case-id 与标签仍来自本轮；不得动态执行文件源码，不得继承历史通过。未知或变化分支保留判断，持续探索及新增设计不被预编写脚本取代。只把已知执行代码准备一次，不要求全模块脚本齐全才开测。

协调者已实际核验当前原生环境支持普通本地文件读写时，在 assignment 标记 `local_artifact_io:true`。执行包直接生成 `browser_bootstrap`：静态公共函数及本轮原始观察导出函数，不重新猜测文件能力。旧受限 cua 环境禁止动态构造函数，不能使用 eval/new Function 或动态加载脚本；普通文件导出不代表支持动态执行源码。静态定义后复用函数执行已知业务及观察导出；普通异常返回 Codex 判断，清理仅在明确结束时执行，不读凭据或浏览器内部状态，不在浏览器调用平台。未验证的环境保留原边界，不臆造能力。真实文件操作失败才沿 JSON 保存，失败原因必须保留。

执行包预置纯函数 `nativeBrowserCase`，在既有原生调用内复用步骤计时、逐项断言、有界只读等待及异常检查点。首次选页仍单独调用并读取文档；初始返回状态直接复用，不再单独重复整页读取。已知操作连续执行，普通异常返回原 observation 和失败步骤；不自动清理或重试业务，由 Codex 读取现场决定下一步。未知业务分支仍需真实判断，不能猜成功。

原生环境已支持本地文件导出时，emit 将实际观察写入本轮 `observation-native.json`；生命周期包用 `input={action:'record',observation_file:本轮路径,finish_task:仅明确结束时为true,browser_stopped:实际关页结果,reason:实际依据}` 直接保存，不经模型重新转录 checks。客户端按原绑定校验 case-id、身份、修订和数据基本结构，原样保留 Codex 提交的状态、断言观察及不可变回执，不再用断言内容推导或拒收业务结论。保存未知暂停下一条并核对原回执，保留现场；明确结束且实际退出后交还。受限环境不支持导出时沿原 JSON 边界保存；不在浏览器读取凭据或调用平台。自动化异常恢复不包含重新执行点击/提交，不将异常改成通过。

native-run-kit 同时返回 `message_arguments={threadId,prompt}`，目标来自原 assignment.executor_ref，命令和执行约束由客户端固定生成。协调者完成原平台 dispatch 后，在同次 functions.exec 把这个对象直接交给已有 send_message_to_thread；若用户明确指定测试模型，仅在这一测试派发调用加相应 model，不改其他会话或 thinking。不要将生成结果输出后再花一个模型回合重写派发消息。生成本身不代表送达；原生工具失败或结果未知不自动重发。端到端统计从协调准备开始，另列准备完到实际消息送达的间隔。

协调者已有本轮 assignment 和选定设计时，派发前运行 `native-run-kit --assignment-file 原文件 --design-file 原设计 --directory 私有目录 --entry-url 已核对入口`（沿用全局 URL/凭据/清单）。生成阶段不领取资源；将返回的 script_file 和直接入口放入派发消息，不让工作者重新找文件、整理参数或编写收尾脚本。工作者按 first_action 先执行环境入口，再用 exec_command 读取这个已核验客户端生成的本地脚本，在同次 functions.exec 通过 `new AsyncFunction('tools','text','ALL_TOOLS','input', source)` 执行 `input={action:'prepare'}`；新任务先执行返回的 environment_setup，再执行该 prepare；ready 后复用独立 Page 进入真实 URL。旧共享在途才继续原 IAB。等待立即结束，实际接续事件才使用相同脚本与 `input={action:'prepare',resume:true}`。

浏览器调用在断言发生处形成 `{case_id,status,checks:[{name,expected,observed,ok}]}`，其中 observed 必须为实际读取值、ok 为已完成比较，不能把点击成功当通过。已知动作和逐项观察合并；需要完整当前状态时使用工具文档的完整快照参数，增量中未重复的旧内容不能当缺失。完成用例后直接把这个对象作为 `input={action:'record',observation:原观察}` 交同一脚本，客户端确定性生成实际结果并保留原始观察，勿另写长篇结果文案。详细证据/检查点仍沿原 native-record 同步，不删减必要信息。保存成功后才能开始下一条。

末条用例可在同一次浏览器调用里记录实际数据清理或已知遗留并关页，然后 record 输入带 `finish_task:true,browser_stopped:true,reason:真实依据`；脚本连续保存、交还、通知后继、发布，无需单独总结回合。pending/unknown 保存保留原观察和回执，不重发、不把未确认内容当作已保存；真实退出后的资源交还仍按原保护处理。明确 rejected/not_sent 仅记录本次保存失败，不阻止发布当前已保存版本，失败内容不计入该报告。仅明确结束任务时记录实际收尾并 closeout；普通错误不自动调用 closeout，不能猜退出。每次调用自动保存独立 cycle 时间记录；完整耗时还须包括消息送达到首条调用、准备完到开页、观察结束到保存之间的间隔，不能只报命令 seconds。

## 固定准备、观察和及时交还

指定设计和任务绑定已提供时，默认使用已核验客户端的三个固定入口，不临时编写 Python、拼基线 JSON 或重读整套说明：

- `native-prepare --assignment-file assignment.json --design-file selected-design.json --directory 原模块目录`：本地核验全部选定设计后，一次连续领取、读取上下文、保存未执行基线和绑定，直接返回实际 case_id、步骤与预期。领取不到资源立即结束；收到原资源事件先用上一节 native-resume 接入通知，确认就绪并准备环境后才带 `--resume` 续领。已成功的准备原样复用，续领仍核对当前授权，不覆盖结果；未知提交保留原阶段，禁止重放。
- `native-observe --binding-file binding.json --case-id 实际ID --status 实际判定 --actual 实际观察 --receipt-file 本条原回执.json`：固定生成单条保存参数，成功后推进修订。详细证据/检查点继续用 native-record，不省略必要断言。前条保存未知时阻止后条记录；浏览器后续动作也必须等保存成功。
- 实际清理并关闭本任务页面后，立即用 `native-closeout-script --binding-file binding.json --browser-stopped --reason 真实退出依据` 生成并在同次 functions.exec 执行原交接脚本。无需再写 final_report、结果统计对象或最终总结；结果枚举从已保存计数生成。新公共脚本先真实交还资源并发送后继，再按原记录发布报告；发布回执未知时保留已交还与发送事实，沿原绑定核对，不重跑业务。旧 bare finish 仍保持兼容。

三个命令均沿用全局 URL、credential-file 和 manifest-file。准备返回 ready=true 才能开始业务；失败立即结束依赖链，不能接着读不存在的文件或开浏览器。若已领到资源而准备失败，binding 仍保留供真实关闭后的交还，不用补造基线。完成后的文字说明和耗时汇总在交还之后进行。通用旧入口保留兼容，不要求在新入口前后再各调用一次。复杂设计、必要侦察、每条独立判定和用户原范围保持不变。

## 一次准备，直接操作

1. 读取本任务目标、资料、已有设计、授权和现场保留设置；内容未变化直接复用。新任务使用 `execution_route=native_browser`；沿用 `direct_test_session` 的 `claim/context/credentials` 取得账号、资料及所分凭据，随后直接执行，不逐动作重新调用。执行者使用实际分配给本模块的账号登录，不自行抢用其他账号。已核验的客户端、当前工具文档、参数结构和保存回执在本轮直接复用；正常执行不穿插源码查询、重复下载工具清单或临时编写传输脚本。只有真实接口错误或能力缺口才查对应单项说明，不能将平台排查扩展成每条用例的准备步骤。
2. 按当前原生工具的文档选定浏览器和标签，并在持久 JavaScript 会话保存页面句柄。仅旧共享环境需要新建页面时使用 `cua.createBrowserTab('iab', url, {visible:false})`；保留 `visible:false`，不能因工具失败移除该参数或自动回退到可见 Chrome。用户明确指定的已有目标及旧在途任务按原归属继续，不迁移或抢用其他任务页面。首次调用的初始化要求沿工具文档执行；后续不反复读取工具目录、浏览器库存或“当前标签”。
3. 直接通过绑定的浏览器工具操作该页面：新任务使用 node_repl/Playwright，旧在途沿原工具。已知输入、点击、对应业务的真实完成等待、局部结果读取和逐项断言写在一次工具调用里连续执行；点击返回、输入框恢复或一次即时采样不代替本次业务完成。稳定定位器、已确认登录态、对象和同轮证据直接复用，不在每个动作后追加全页 `getAXState()`。未知分支、真实差异或工具异常需要判断时再返回模型。
4. 每条用例有独立输入、预期、观察、结论和证据关联。完成一条就调用原结果保存入口增量同步，再继续下一条；不为每个点击保存或读取平台状态。一个用例内的多组输入可以连续执行，各组观察不得合并丢失。
5. 依照原现场保留设置收尾，保存真实未完成、阻塞及清理结果，发布原轮报告；不为补报告重新执行业务。

平台不代理浏览器，也不在每个动作前后执行 `operation_begin`、账号重领、业务请求批准、动作排队、`browser/result` 轮询或额外心跳。平台客户端可用于账号、资料、结果和证据传输，但不能包裹或转发浏览器动作。不得为了沿用旧 helper，新增本机控制服务、stdin 桥、HTTP 浏览器服务或另一套 Runner。

隐藏页面只控制显示，不证明 Cookie、缓存或登录态隔离。多账号并发须有真实独立登录环境；同一 profile 按上面的真实容量排队并沿原任务接续，不能把多个隐藏标签、不同 Codex 聊天当作隔离。只登录本模块已分配的账号，不为切换账号退出、覆盖或借用其他任务的登录态；独立能力不足记录为环境容量或接入缺口，不把未核实身份写成账号不一致。

用户已允许原生探索共享账号，仅由 Skill 约束操作，并接受没有逐请求拦截的剩余风险。平台分配共享探索或独占账号；共享成员按约定探索，遇到需要写入或进入执行阶段时才在该真实边界申请独占，不自行升级权限、不逐动作查询平台。账号/标签/业务对象的归属只在实际取得、交接、冲突或结束边界处理，不把这些边界展开成每次点击的远程检查。共享账号是否可用以平台已分配的真实能力为准；原生浏览器的共享约束由 Skill 执行，不声称保留旧 Runner 请求策略拦截或自动核验。平台管理共享成员的分配、退出和转独占；原生页面仍直接使用工具，没有 Cookie 导出/注入及逐动作代理。

## 结构变化与空白页恢复

定位器只在页面结构仍相同时复用。弹窗变为页内详情、切换列表入口等真实边界发生后，依据当前页面的必要区域重新定位；首次无匹配时核对实际结构，不能反复等待旧弹窗或旧区域直到超时。已经发生的点击及其后取得的有效观察保留，定位失败不表示前面的业务动作没有发生。

等待最终结果时也识别当前页面实际出现的中间步骤和失败状态。例如出现待确认表单后先处理该表单，不继续盲等下载入口。导航后确认目标 URL 或目标内容已经提交，再执行刷新；不能仅凭一个从未确认出现的加载文案已隐藏认定完成。同次可读取的局部计数、状态标签和必要证据一起取得，随后沿原结果入口保存，不为整理结论重复读取已确认状态。

只有定位超时、空快照或句柄异常时，才在同次工具调用的异常分支读取原绑定标签的 URL 和页面状态，把异常、时间及已完成检查点一起保存；方法以当前原生工具文档为准，例如已有 `tab.url()` 和 `tab.getAXState()`。正常步骤不增加这些探针。空 DOM 单独不足以证明页面导航到了空白，URL 与页面状态确认为 `about:blank` 后，且原入口已经核实只用于读取、没有在途业务写入或未保存输入时，才在同一原标签对该地址恢复一次，并等待实际目标控件就绪。原句柄已经失效时，按浏览器控制约定重新定位归属明确的本轮标签；仍不可用就保存具体恢复条件，不继续循环导航或创建页面。

恢复后只补原检查点的未完成读取，保留已有用例、证据与结果；写入结果未知时先核实原业务状态，绝不因空白重发收藏、提交或删除。恢复继续使用原授权账号与隐藏页面，不移除 `visible:false`、不切到可见 Chrome、不借用其他任务标签。上述约定减少失效定位和恢复往返，不证明站点或 IAB 自行进入空白页的底层原因已经修复。

## 连续执行与逐条同步

连续执行的单位由业务决定，不预设条数或删减边界。例如搜索用例已经明确输入及预期时，在同一工具调用内按顺序填入各组值、读取对应区域并逐组保存观察；不要为每组输入重新开终端、查询平台回执或返回模型规划下一次输入。存在不同初态、角色或副作用的用例仍各自建立前置并独立判定。

单次调用完成多个检查点不等于多个独立用例都可延迟回写。按当前工具公开能力组织已知链路：能连续完成的动作、真实完成等待和局部断言放在同一次原生调用，未知分支或真实异常仍返回判断。未提供同调用保存或外层原生编排能力时，在用例完成边界返回真实结果并立即保存，成功后再开始下一条；不要把“逐条同步”误实现成每个点击一次模型回合，也不要为批量运行而等模块结束才保存。

原生会话只使用当前工具公开允许的 API；不能因需要同步结果而在受限 `cua` 中导入本地模块、读取凭据、发任意网络请求或访问浏览器内部状态。外层工具清单未暴露原生浏览器能力时，不能编造 `tools.mcp__cua_repl__js`，也不能把账号交接可编排误当浏览器也可编排；直接调用原生工具，在用例完成边界调用下述标准记录入口，不另造代理。只有实际工具清单明确提供相应能力时才可编排，不作为本路径前置。批次按共享初态和业务依赖组织，不设固定调用数、用例数或等待额度；已知步骤连续完成，保存失败、未知写入及真实差异仍保留原停止边界。

结果保存沿用 `save_ui_test_cases` 的 `project_id`、`execution_id`、最新 `revision` 和稳定 `case_id`；只提交该条变化及检查点。必要证据取自真实现场，失败先取证再恢复。保存失败先保留本地观察及待保存数据，只补传结果，不重演已经完成的业务动作；响应不明时核对原保存结果，不能盲目另建轮次。已有确定成功回执不再额外读全量用例“复核”。

### 标准原生结果记录入口

有终端时使用已核验客户端的 `native-record`，不为每条结果另写 Python 包装或手工增减 revision。开始时从本轮已有 claim/context/保存回执准备一次私有 `binding.json`，包含 `holder_id/task_id/node_id/lease_id/project_id/execution_id/revision`，可带 `account_id`；原文件已经包含这些字段就直接复用。绑定值来自真实回执，不猜测，也不为每次保存重新 claim/context。此入口只传输平台记录，不运行浏览器、不判断用例通过；普通结果逐条立即保存。最终回查可只传 `coverage/review_notes/scene_outcome/experiment`，或最多 200 条确有变化的 `cases`，不重发全部用例。

```sh
# case-result.json 仅含刚完成用例的真实变化，例如 {"cases":[{"case_id":"原编号","status":"真实状态","actual":"实际观察"}]}。
# 每次新的保存使用独立回执路径；清单是本次已核验的同源下载，保留客户端摘要匹配。
python3 "$CLIENT_PATH" --url "$WORKSPACE_URL" --manifest-file "$MANIFEST_PATH" native-record \
  --binding-file binding.json --input-file case-result.json --receipt-file case-save-receipt.json \
  --output-file case-save-summary.json
```

`--manifest-file` 可选；复用时在本地核对所用工具和参数，不逐条重新下载工具清单。`native-record` 调用原 `direct_test_session(action="record",record_action="cases",arguments={...真实变化,response:"summary"})`，保留修订、真实状态计数、变化编号、执行计划和全部动态提醒，省去重复固定说明。成功回执持久保存后原子更新绑定的最新 revision。使用 `--output-file` 时终端只显示保存路径、成功标记、轮次修订、进度与耗时，完整动态提醒和执行计划原样保存在回执及输出文件；需要处理动态项时，在同次 shell 调用中定向读取对应字段，不再通过 HTTP 重读全量用例。`client_timing` 记录方法开始至收到并校验响应的 UTC 开始/结束时间、实际秒数和 HTTP 次数；进程启动与末尾持久写盘计入外层命令实测耗时，不将两者混为业务耗时。重取成功回执的 `http_calls=0` 并保留原保存时间，不计为新的业务执行或保存。只有安装版 MCP 时沿用相同 `record` 入口并复用保存回执，不为了 CLI 更换环境。

本地回执先保存 pending，再提交一次原请求；相同输入的 saved 回执重取只读原结果，不能据此重跑业务。pending/unknown 须保留观察并沿原请求、绑定和修订核对，不自动重发。明确 rejected/not_sent 是失败回执，不等于未知实际操作，不阻止发布当前已保存版本；未保存的内容不能说成已在报告中。需要补交时修正具体原因、同步最新绑定 revision，并用新回执保存已有观察；不删除旧回执、不直接重跑旧 pending 命令、不重演浏览器动作。绑定或修订冲突也不重建轮次。最后没有新事实时直接沿用已保存结果收尾，不为计数、文案或同一证据再次提交。

原 unknown 已用独立成功回执补存、且修订已超过原精确读回范围时，停止接收器后显式执行 `native-reconcile-observation --binding-file 原绑定 --request-id 原观察ID --correction-receipt-file 独立成功回执`（保留原客户端的 url/credential/manifest 参数）。入口只读一次原记录，核对原请求/完整字段/身份/指纹/修订/时序，另存 `native-observation-correction-原观察ID.json` 后正式结清匹配 pending；原 unknown 和失败证据不改成成功。其他 pending、错配或未知仍受保护；正常精确读回继续使用原 `nativeReceipt(request_id,{reconcile:true})`。已确认关联在同身份正常修订推进后可本地复用，不重读、不重发保存，不代表报告已发布或浏览器已退出。该CLI拒绝仍持有本地锁的活动接收器，不创建竞争接收器。

## 一次合并收尾

最终变化通过原缓存生命周期 `input={action:"review",input_file:变化文件绝对路径,receipt_file:本次回执绝对路径}` 保存。变化 JSON 可带 `asset_files`（最多 50 项，沿原上传清单的 `file/case_id/step/kind/captured_at` 字段），证据与变化同一请求落盘，不与另一个 `upload-files` 或裸 `record/finish` 并发竞争修订。服务端一次返回数据结构、归属或修订问题，本批失败不保存部分结果；客户端区分明确 rejected 与 unknown 回执，保留已有观察，不重演业务。final_review 仅记录本次保存回执，不评价覆盖或证据充分性；明确拒绝不阻断当前已保存版本发布，pending/unknown 仍须核对。成功回执把实际保存的变化用例和覆盖清单同步回本地原设计；无需全量读取。既有 `upload-files` 保留兼容并返回实际 revision，但不能与原绑定写入并发。

没有新变化就直接 `closeout`，不为了报告另写总结。已有真实退出依据时，review 可同次带 `finish_task:true,browser_stopped:true,reason`，保存后沿原交还、通知后继、发布链路完成；保存未知时只按真实退出事实交还，不把未确认结果发布为完整报告。普通失败不自动关闭浏览器或结束任务。

原生模块先记录实际数据收尾结果（含已知遗留）并关闭本任务页面，再沿 `native-handoff-script --binding-file binding.json --args-file finish.json` 收尾。全局 `--manifest-file` 会传入交接的每次原平台调用，复用已核验清单。`finish.json` 保留 `action:"finish"`、真实 reason 和 `arguments.browser_stopped:true`；`arguments.result` 使用 passed/failed/partial/blocked/not_run 字符串，不传统计对象；可选 `arguments.final_report` 携带 title/summary、scene_outcome、experiment 及确实尚未保存的变化，身份和最新修订由原绑定补齐。省略 summary 使用已保存结果自动汇总；不要为了报告重读全量用例或改写全部文案。

带原绑定的新固定 closeout 编排先按退出事务交还并实际通知原后继，再通过原 record/publish 发布已保存修订，返回 `publication` 和真实交接回执。旧裸 finish 的合并总结兼容入口保持，不代表已执行通知编排。不得先发总结再补结束时间，也不在交还后另发相同发布请求。`publication.phase=published` 才代表报告已发布；失败或 changed 如实保留，不影响已完成交还，不重跑业务。未知 HTTP 响应仍沿原事件核对，不盲目重提。

逐条 `native-record` 可同时携带已有 `experiment` 时间记录；它不推算时间、状态或模型。准备资料按原目标直接复用，只有内容、角色或条件变化才更新；已验证的文件直接使用。新增依赖时用原返回的依赖标识记录真实检查，再保存依赖结果；不在结果被拒绝后才重复整理。等待使用当前工具支持的真实状态条件，同时识别已观察到的中间步骤或错误；发生后立即处理该状态，不继续等待失效的旧终点，不通过固定睡眠或每次全页读取替代业务完成。

## 原生资源与模型状态（0.17.87）

原生路线不使用旧 Runner 的 `model_slots`；模型容量、启动失败和运行异常独立于账号及浏览器资源。平台不能自动观察外部桌面的 `turn.error`，不能将模型错误写成“账号不足”。原执行者或原绑定协调会话通过已有 `direct_test_session(action="dispatch")`、稳定 `request_id` 回报 `arguments.executor_status`：

```json
{"node_id":"原节点","task_revision":1,"node_revision":1,"holder_id":"原执行者","dispatch_id":"原派发","executor_ref":"原真实thread ID","state":"unavailable","source":"codex_turn_error","reference":"实际桌面事件引用","model":"原实际模型","kind":"capacity","reason":"已观察到的简短模型错误"}
```

`kind` 支持 `capacity/startup_error/runtime_error`；版本和绑定来自原派发/状态回执，不猜 ID，不把网页或提示词内容当作桌面错误。无租约时仅取消未生效预留与提名，不占账号；已有租约、未知动作或保留现场仍须沿原真实退出流程交还。原执行者再次实际 `claim` 会结清过期异常和上次唤醒等待，沿原模型、原会话、原检查点及保存结果继续；领取竞争失败仍结束当前回合，后续真实资源变化才可重新提名。显式恢复回执用 `state=available/source=codex_turn_started`，保留同一模型，并以 `resolves_reference` 对应当前错误。以上不新增重试次数、定时唤醒或自动切模型。

`account_ids` 缺省语义是必须具备的完整账号集合，旧明确多账号业务要求当前按全局规则不测，不能删减账号后冒充已验证。只有确实是历史偏好时使用 `account_selection=preferred`（固定准备放在 `assignment.claim_arguments`）；实际环境、租户、角色与账号集合仍由原调度校验。省略账号参数保留旧要求，显式 `account_ids=[]` 清除旧选择；检查点的历史账号只是偏好，不代替当前硬身份约束。

环境以实际创建/退出和原派发生命周期判断，不通过修改旧 `native_environment_revision` 假装有效。无关节点修订不让仍有效的环境失效；停止、撤权、真实退出和旧未知现场保护保持。已确认退出的独立 Chromium 必须真实准备新环境，不能重报旧 ID。

通知仅提供领取机会，不是资源占用。暂时不可用记为 `waiting_resources`，条件变化后可重新匹配；仅同次资源变化的提名共享临时预算，历史 pending/sent/unknown 不作为账号租约。发送占用与未知消息保护照旧。账号/环境/依赖/模型状态变化由原调度统一匹配，`pending_handoffs` 只表示待真实桌面工具发送/消费，没有已核实的后台 relay。不得把服务器持久化事件说成原聊天已收到。

必要结果/检查点先保存，确认真实浏览器退出后，原事务释放账号并写 `resource_change.at`；匹配时间为 `matched_at`，实际发送开始/确认分别为 `delivery_started_at/sent_at`，原执行者实际响应为 `claim_received_at`，成功领取还须核对真实 lease。新生成的带绑定 closeout 编排先交还并通知后继，再沿原 record/publish 发布已存结果，报告失败不撤销交还或发送事实；已确认 published 后的通知错误也不能降级报告状态。原裸 finish 兼容，不等于执行了这段编排。

## 没有账号或没有进展

平台返回未分配账号时，保存原任务、模块、会话及续测位置，结束当前执行回合。不得运行领取循环、模型定时唤醒、重复 `wait_threads` 或依靠不断发“继续”占用额度。平台保留排队；只有收到真实资源变化并且存在已核实的会话唤醒能力，才唤醒原会话。没有这种能力时说明待唤醒事实，不宣称已经自动恢复。

实际缺少验证码处理、凭据、权益、设备或入口等条件时，记录一次已核实的原因、影响用例和恢复条件，继续独立可执行分支；不重复相同失败、不增加无关检查或重新生成整套设计。尚未做但在本轮授权内可完成的准备不是客观阻塞，应直接完成。持续探索和新发现的增量设计保持不变。

## 本模块交还与通知

真实退出后，使用原 `native-closeout-script` 或执行包 closeout/release 生成并在同次 functions.exec 执行。生成器先交还账号、机械发送实际可用原后继并保存原回执，再处理报告；不需要执行者承担其他模块的调度或汇总。发送/消费/实际领取分别记录，`needs_handoff` 和 `handoff_failures` 说明未落实的原事件、目标和阶段。缺消息工具时无法发送；未知不重发，保留原回执供协调者核实。单模块未绑定协调者不制造交接通知。详见协调参考中的原交接字段，仅协调者消费组级异常。

## S1 停止：平台停止与桌面停止分别确认

用户已选 S1，不把它描述成平台能强制取消桌面 Codex：

1. 平台停止本任务后续派发和排队，保留结果，并列出本任务尚未确认结束的实际桌面会话。
2. 用户在这些桌面会话点击停止。执行者一旦收到停止，不再启动下一条业务动作；停止不以补齐报告、清理数据或完成当前模块为前置。
3. 核对本任务浏览器工具调用/脚本是否已经结束；只处理归属明确的本任务浏览器资源，不关闭其他用户标签或按浏览器名称杀进程。
4. 通过原生 `direct_test_session(action="finish")` 的 `arguments={browser_stopped:true,reason:真实核对依据}` 交还账号；只在真实核实浏览器控制结束后填写。来源是执行者报告或用户确认，不能写成平台独立验证。桌面回合停止、浏览器动作结束和账号交还分别记录。未核实退出时保留实际占用，不把平台停止按钮、已发送消息或零租约当成桌面推理已取消。

当前没有已核实的官方入口让平台直接强制取消任意桌面会话。发“停止”消息、归档聊天、停止轮询或断开平台连接都不能冒充取消。不得未经用户选择迁移到 app-server、后台 API 模型、Playwright MCP 或其他控制后端。

提交 `finish_test_workflow` 后若返回 `native_closeout_required`，按 `required_sessions` 中的原会话完成真实退出/交还；未接单的 `required_modules` 通过原无租约结束入口保留未执行结果。不要轮询工作流状态等待这些动作自动发生，也不要重复保存最后一批用例。`manual_stop_required` 表示仍有桌面会话/浏览器退出待核实，不能把已保存结果或待退出回执当成最终报告已完成。

## 实际记录验收

从正常业务调用记录核对原生工具名称、开始/结束时间、连续输入及各项观察、实际用例结果保存时间、错误与恢复动作。按实际边界分别记录准备、业务执行（含本次真实等待）、结果保存、证据传输、数据及浏览器收尾、报告整合与发布、资源交接的开始/结束时间和耗时；暂停、排队及无法归因区间另列。工具区间与阶段区间可能重叠，不直接相加；没有证据的区间标未知，不猜为模型思考或服务处理。

效率验收同时核对执行路径和实际时间：准备是否直接复用、已知操作是否连续、是否存在逐动作全页观察、重复查询、重复业务、临时传输代码或重复收尾，并列出剩余开销。已有时间对照直接使用；相同片段保持输入、必要断言和模型档位，跨模块则说明不同的业务等待、数据准备及报告整合，不能以不可逐秒等同比较为由忽略已有记录，也不能把用例数相同当成工作量相同。时间是发现低效环节的证据，不以固定分钟数截断测试或删减用例。工具接通、代码上线、路径落实和真实效率分别报告；测试执行使用用户指定的模型，不改变开发、排查或审查模型。任何必要断言、用例或证据被删减，不能判提速验收通过。

已核验的持久原生会话用 `browser_routine_file` 与 `browser_runtime_receipt` 按代码摘要注册静态函数一次；回执匹配本执行会话时后续只发送短调用，传本次 tab/case_id/directory，不捕获旧账号、标签或结果。旧受限 cua 不使用 eval/动态导入本地代码；会话重置在业务前停止并重载同版一次。首次加载另列耗时，不隐藏在准备外。`native-prepare --receive-observations` 在同一进程准备并输出接收就绪回执，失败不继续。`closeout,from_observation:true` 使用本轮真实退出回执，不再次拼总结。交接通知到达先核对原 task/node/event，下一次工作调用立即 ACK，再读报告；已发送不等于已收到，ACK 不等于用例通过。

0.17.58 通用入口：所有已核验 `local_observation_stream` 执行包默认启用公共函数跨模块复用，不要求预写业务脚本或新增配置；旧 `browser_call_file` 自动接入例程缓存。默认私有加载回执按执行会话与代码摘要隔离。未知新模块照常侦察、生成具体设计、边执行边增补及独立判定，只复用准备/保存/收尾公共代码，不能复用历史通过或其他模块断言。


0.17.62 公共执行链路：已初始化且真实内存摘要匹配的已知用例，短调用先验证函数存在，再连续创建隐藏标签并调用已加载代码；未加载、重置及未知业务仍走原入口和文档要求。开页失败不执行用例，不删除用例内账号/前置/退出断言。新交接确认只在原事务核对一次；幂等缓存回执仍按当前停止、删除与修订重新核对。不存在候选后继时跳过历史节点/账号深复制与调度预览，但先保留全局失效事件清理；有候选或已有事件仍走原公平性、账号及发送保护。


0.17.63 公共准备、交还与最终交付：会话元数据仅读取一次并沿原路径/owner/软删除校验；已关闭探索批次只在真实状态变化时记录关闭时间，资源池与新持有人检查保留。原轮报告实际 published 后精确核对节点、执行与结果修订并清理待收尾标记，避免后台重复收尾；匹配变化保留 pending，清标记异常只告警，不把已发布报告降级为失败。交还及每段发送回执保留服务端分段计时。
执行包在明确起点记录 run-ledger（未提供更早起点时仅从kit开始计时）；已加载单用例准备后直接返回绑定真实case_id的native_call，多用例保留原调用和完整设计，保存过的用例不由该入口重放。每次原生调用写独立计时，不覆盖其他用例。返回的 delivery_script_file 由原协调会话在真实交接通知后执行 input={task_id,node_id,event_id}：核对原绑定、确认、保存原回执、一次核验并生成最终JSON/HTML与可直接回复摘要。发布回执在通知前持久保存，不轮询等待worker收尾日志；缺失阶段明确未知。总耗时从明确起点到最终报告生成，重叠只计一次，不冒称聊天已发送。原用例粒度、探索增补、独立断言、账号隔离、停止、队列公平性、发送占用、未知不重发及旧入口保持。


## 0.17.81：记录与交还连续衔接

- 每条真实 observation 可同时提供 `case_changes`（steps、test_data、checkpoints、action_context 等原用例变化）和 `asset_files`，与该条 checks 的实际结果一次保存；不等收尾再补整批步骤和附件。不推断未观察的操作，不改变判定、持续探索及独立用例。
- 缓存的生命周期函数仍只传短参数。保存回执中的动态缺口和本地 design.json 是回查输入，不重新查询平台全量结果或重写计数。没有新事实不重存、不重跑。
- 实际清理并核实浏览器退出后，如还需要整理报告，立即调用 `{action:"release",from_observation:true}`，或明确 `browser_stopped:true` 和真实 reason。同次完成原账号交还和后继通知，返回回查材料。没有实际退出不得调用；普通定位或保存错误不自动关页。
- 报告补齐后调用 `{action:"complete",input_file:变化文件,receipt_file:原目录新回执}`；无变化只传 `{action:"complete"}`。原 holder 在原任务、节点、轮次、派发代际下补保存并发布，不重新 claim。报告自动汇总原记录，不需要模型再写大段总结。
- release 后接收器仅用于原观察回执核对，最终发布才退出；未知结果不重传。报告失败保留原记录和回执，账号不再占用，不能虚称最终交付。真实发布后才发送尚未发送的整组结束通知；后继接续无需等待报告。
- `review` 单独调用仍只保存。明确 `finish_task:true` 且实际浏览器已退出时，先交还再保存并发布。旧 closeout 仍一次交还并发布已存结果，不迁移在途包、不新增模型等待。
