# 浏览器和数据收尾

启动前记录已打开的用户窗口/标签与本次资源归属；每创建一个标签、上下文、浏览器、原生文件选择框或驱动进程，就在本轮内部资源清单记下可识别的 ID/句柄。任务明确结束、停止或无法继续时执行资源收尾；普通定位/保存错误保留当前现场，不自动关闭浏览器。在明确结束时使用 finally 或等效收尾；报告发布成功不能代替资源收尾：

1. 停止本次测试脚本、重试循环和自动化控制。
2. 关闭本次打开的原生文件选择框和驱动进程；非保留范围内的本轮标签、上下文、会话和浏览器也要关闭。若选择“保留完整测试现场”，可在工具支持且归属明确时保留本轮页面/标签的可见状态，但仍须停止脚本并释放自动化控制，不能连驱动进程一起遗留。复用用户浏览器时不退出其原有浏览器，也不关闭其他任务资源。
3. 对照启动前快照和资源清单，核对本轮资源的已关闭或有意保留状态；关闭接口成功不是验证完成。重新拉起时检查本次启动者/守护程序。
4. 不能正常关闭时只对已核实属于本次任务的PID/会话逐级终止，禁止按Chrome名称全量杀进程。归属不明则准确报告遗留项。
5. 沿用已读取的 `get_test_document.scene_retention` 本轮设置，实际设置变化时才重取，默认 `none`：清理并核实本轮可确认归属的测试数据。`defects`：只保留复现失败用例所必需的本轮对象，其余清理。`test_data`：保留本轮新建的数据/文件，恢复本轮改动的共享配置。`full`：不主动清理本轮归属明确的业务现场，并尽可能保留可见的本轮页面。无论哪档，均不得清理用户既有或归属不明的数据；无法恢复的共享配置如实记录，不能冒充已恢复。检查列表、搜索、记忆等关联入口残留。
6. 截图、录屏、报告和上传到报告的夹具不受现场选项影响，始终保留。现场对象与用途要可复现，记录对应用例及保留/清理/未核实状态；即使保留现场，仍交付数据重建步骤。
7. 清理任务专用临时下载与过时交付，不自动生成桌面交付物。用 `save_ui_test_cases(cases:[],scene_outcome:{status,note,items})` 回写实际收尾：status 为 `cleaned`/`retained`/`partial`/`unverified`，items 列出对象的 `case_id,name,kind,state,reason`，state 为 `retained`/`cleaned`/`unverified`。未核实不能写成已清理；后续用户要求清理保留现场时，可按这份清单重新核对并执行，不凭旧报告直接删除。最终回复明确说明本轮浏览器资源是否已清空。

清理遵循执行参考的失败停止条件：同条件下已确认的删除失败，停止该组对象的重复尝试，记录残留；持续加载且无法核实时也停止后续同组写入。其他类型的数据、共享配置和浏览器资源分别收尾。用户无需叫停才终止无效清理，partial/unverified 是如实交付结果，不能假记 cleaned。

Codex 判断清理结论并原样记录业务描述；登记清理责任时用 `business_completed` 和原操作 `original_operation_resolved` 明确事实，见 [原操作清理核实](execution-recovery.md)。已核实未清理或已知遗留不等于继续占用账号；真实退出后按原流程交还。未知实际操作、在途控制和明确保留物理现场的责任仍按原保护处理，不通过换词、删记录或新操作解除。

收尾时根据实际结果说明本轮目标达成程度、重要规则与链路的验证情况、缺陷和剩余范围；同时核对数据可复现与资源归属。存在未测项时准确描述，不宣称全部测完；这些要求不是平台发布的强制门禁。
