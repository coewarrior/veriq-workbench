# 接口测试
## 当前平台全局范围（2026-10-26）

当前平台全局范围：多账号、双账号、跨账号及跨租户对照/隔离业务场景一律不测（用户明确排除多账号场景）。保留具体设计和已有真实结果；未执行项使用 not_run，not_run_reason 填写上述原因；UI cases.account_scope、API design.account_scope 使用 multi_account/cross_account/cross_tenant 明确范围。不算通过，不申请第二账号、不等待账号集合、不为其创建执行会话或续接，不另做替代测试。普通继续测试/重测不解除此规则。不同模块各用一个账号并发仍允许；单账号权限、匿名及其他适用风险覆盖保持。已有真实对象责任的必要清理和无需账号的报告仍按原授权及回收协议处理，不扩展业务测试。

此明确范围变更优先于下文历史多账号示例；既有隔离、授权、清理及回收协议仍保护历史现场，不授权发起新多账号业务。


目标是发现真实问题并说明测试范围，不是完成一张固定维度表。根据接口语义、业务流程、数据状态和风险自主决定用例数量与深度。

## 先理解测试对象

1. 确认用户要文档审查、用例设计、完整执行还是指定范围回归。只做文档审查时直接检查契约、规则和缺口，不发送测试请求。
2. 读取范围内完整文档及相关 Schema、业务规则、已有用例和历史问题。列出接口、输入输出、鉴权、状态、副作用和依赖关系。
3. 预期结果以文档、用户确认的规则或明确质量要求为依据。资料不一致或预期未知时说明缺口，不把接口当前返回值当作正确答案。

## 设计测试

对范围内每个接口，至少设计并实际展开以下四类场景；一类可以有多条用例，不能只写类别名称或用一条笼统用例代替明显不同的分支。

- **正向测试**：合法输入、主要成功分支、可选参数、默认值、返回内容和业务副作用。
- **逆向测试**：缺失或错误输入、错误类型和格式、无效状态、认证与权限失败、依赖失败及文档声明的错误分支。
- **边界情况**：空值、最小值、最大值及边界两侧、长度、数值精度、时间、分页和容量边界。没有依据的阈值不硬编。
- **安全测试**：根据实际攻击面检查认证绕过、越权与数据隔离、注入、敏感信息泄露、路径或地址操控、文件风险、滥用与限流。具有破坏性或压力性质的项目只在合适环境和授权范围执行。

完成最低覆盖后，继续根据接口特点主动扩充：业务规则与计算、参数组合、状态流转、多接口链路、数据一致性、幂等与重复请求、并发竞争、异常恢复、性能、文件与异步任务、版本兼容等。可按需读取 [扩展测试思路](references/test-dimensions.md)，它是启发清单，不要求逐项填写。

用例数量不设固定上限，也不以“每个接口四条”作为完成标准。分支多、风险高或输入复杂的接口应自然产生更多测试；简单接口可以较少，但须能说明主要行为和风险已经怎样覆盖。已有用例可复用、改进或合并，不能因此忽略其中仍然有效的业务要求。

## 让用例可判断

用例 `title` 按“场景／操作 → 预期行为”写成自然中文短句，例如“密码错误时拒绝登录并提示密码错误”；只看标题就能知道验证点，标题中的预期不代表实测通过。每条围绕一个独立业务判断；端到端链路保留业务终点，不按点击拆分。规则未知时明确待确认，不为写完整标题编造阈值或行为。

前置条件只放业务初态与必要依赖，输入写具体对象及完整参数，请求步骤写编号操作，预期写可观察结果和通过判据。公共登录、入口确认和样本准备写入准备说明或前置/步骤；登录等本身属于目标时仍保留独立规则用例。执行纪律保留在执行规范，不逐条塞进前置。

保存前核对标题、输入、步骤和预期引用同一对象，名称、ID、文件及输入值一致；有意对照不同对象时说明各自用途。未知数据写待准备/核对，不猜造。优化表达不改变已有目标、断言、测试事实或状态，不删完整输入与复现细节。

每条用例写清稳定 ID、目标接口或链路、场景类别、前置条件、输入、请求步骤、关键断言、预期依据、后置验证以及必要的清理安排。

- 不只验证 HTTP 状态；按场景检查业务值、身份、集合、状态变化或副作用。
- 负向用例尽量只改变目标条件，避免多个错误互相遮挡。
- 多步骤链路可以传递 ID、Cookie 或 Token；独立用例使用独立数据和会话。
- 先完成完整的具体用例设计，再安排执行。缺少规则、账号、测试地址或工具能力时，仍保存该用例的前置条件、输入、步骤、预期与依据及具体阻塞原因；不能只留一句测试想法，更不能从设计清单删除。继续解决可修正的阻塞并执行其他用例。

长文档按接口分别展开设计，另看跨接口链路。先保存具体设计，再分批补齐执行格式；某条的清理或断言格式暂未解决，不应让后续接口停止设计。编译时保留原设计，核对有没有漏掉输入变体、业务分支或整条用例。

需要记录覆盖情况时，使用 [简洁覆盖记录](references/coverage-records.md)。记录服务于查漏和报告，不要求固定表格、固定字段或固定数量。

## 执行与回查

用户要求真实测试时，优先使用指定工具。接入本测试台时读取 [测试台执行约定](references/workspace-execution.md) 和服务当前工具格式。

先运行核心正向链路和高风险场景，再覆盖其余可执行用例。保存真实请求、响应、断言、清理结果和运行标识；敏感信息脱敏。失败时判断是产品行为、测试设计、目标服务还是工具问题，修正可确认的问题后再测，不能为了通过删除有效断言。

执行后按实际结果回看四类最低覆盖和接口特有风险：若某类只有标题、没有具体用例或没有有效断言，应补充；若无法执行，明确列为未执行或受阻。不要因为已有若干通过用例就停止扩展。

## 交付

输出中文可视化报告或用户指定格式，说明：测试范围、四类最低覆盖、根据接口特点新增的场景、真实执行结果与证据、发现的问题、未执行或待确认项目、测试数据清理情况。

通过率只描述已执行用例的结果，不代表接口行为已经全部覆盖。结论应让用户看出测了什么、为什么这样设计、还缺什么，而不是只给用例总数。
