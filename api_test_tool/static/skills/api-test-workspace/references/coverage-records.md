# 简洁覆盖记录

覆盖记录用于发现遗漏，不要求固定模板。Markdown、JSON、CSV 或报告章节均可，只要能从场景追溯到用例和执行结果。

至少能回答：

| 接口或业务链路 | 场景 | 类别 | 用例 | 预期依据 | 结果或缺口 |
| --- | --- | --- | --- | --- | --- |
| POST /login | 合法账号登录 | 正向 | LOGIN-01 | 文档登录成功响应 | 通过，见运行记录 |
| POST /login | 密码长度下界两侧 | 边界 | LOGIN-07、LOGIN-08 | Schema 最小长度 | 待执行 |

四类最低覆盖按接口汇总即可：正向、逆向、边界、安全。每类应列出具体场景或明确说明为何当前接口没有可设计的场景；不需要再拆成固定数量的维度行。

对于接口特有风险，直接增加类别或标签，例如业务规则、状态、链路、数据一致性、幂等、并发、恢复、性能、文件、异步或兼容性。一个用例可以关联多个场景，但实际执行时仍按发生的步骤和断言判断哪些场景得到验证。

用户提供已有用例时，优先保留其中有效的业务条件和断言。需要正式对照时再记录原用例与新用例的映射；普通测试不必为每个原 ID 建立额外表格。

报告简要说明已设计、已执行、通过、失败、异常、受阻和未执行的数量。无法确定完整分母时，不编造覆盖率；用具体场景和缺口说明当前覆盖程度。完整设计和逐条执行证据分别从用例设计页、执行报告查看，不要在分析报告中复制成长附录。
