# 扩展测试思路

需要补充四类最低场景时按接口特点选用。这里是启发清单，不要求逐项判断，也不要求每项都生成用例。

## 业务与流程

- 不同合法业务分支、条件优先级、计算与舍入、配额和时间规则。
- 创建后查询、修改后回读、删除后确认、非目标数据不变。
- 合法与非法状态转换、重复操作、终态操作、撤销与恢复。
- 多接口成功链路、前置失败、部分成功、跨接口数据传递和副作用。

## 输入、协议与响应

- 必填、null、空字符串、空集合、类型、格式、编码、特殊字符和字段组合。
- 方法、路径、查询、Content-Type、请求头、空正文、畸形正文、多余或重复字段。
- 状态码、业务码、响应结构、错误结构、字段类型、可空性和敏感字段。
- 筛选、排序、分页、空结果、不存在资源、页间重复或遗漏。

## 身份与安全

- 未认证、无效或过期凭据、注销失效、刷新和重复登录。
- 角色权限、资源归属、跨用户或租户访问、管理字段越权。
- 注入、路径穿越、SSRF、批量赋值、恶意文件、暴力尝试、限流和信息泄露。

## 稳定性与数据

- 重复请求、幂等键、超时后重试、并发创建或修改、唯一约束和竞争条件。
- 依赖故障、断连、超时、部分失败、回滚、补偿和恢复后状态。
- 最终一致性、缓存更新、消息重复或丢失，以及清理失败后的影响。

## 性能与特殊能力

- 延迟、吞吐、大请求或大结果、持续与峰值负载、资源消耗和恢复。
- 上传下载、文件类型与大小、异步任务、Webhook、流式响应和中断重连。
- 新旧版本、旧客户端参数、时区、序列化和协议兼容。

从文档中的条件语句、错误说明、状态变化和已知缺陷继续发现场景。接口越复杂、风险越高，展开应越深入；没有相应能力时直接跳过，不需要写一行“不适用”。
