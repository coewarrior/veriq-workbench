# 原生执行公共链路整改（0.17.71）

## 经用户确认的边界

Codex 观察和操作 → 工具返回结果 → Codex 判断下一步。平台负责账号分配/占用、真实独立环境、原并发规则、用例和结果记录；不插入逐次点击授权。普通定位失败是可恢复观察，不自动转成业务失败、关闭浏览器、交还账号或结束任务。

## 实施清单

| 保留 | 删除或替换 |
|---|---|
| 原任务/节点/账号队列、共享探索与独占规则 | 不新增串行限制、任务或模型配置 |
| 公共函数一次加载和短调用、准备缓存 | 取消 mandatory run/recover/close 整体包装；公共 journal 仅可选 |
| 已知动作合并、真实等待和独立断言 | 删除异常时补造 execution completed=false 断言和 finally close |
| 原用例、基线、已存结果、证据、审计 | 普通异常返回 interrupted 草稿、失败位置和逐步耗时，交回 Codex 判断 |
| 原逐条保存和不可变回执 | 保存等待有界返回 pending；不把 pending 当业务失败或退出许可 |
| 原报告确定性生成、定向交接、收到后立即 ACK | record 只保存；仅明确 finish_task/closeout 才结束并释放 |
| 真实账号隔离、原 Page 直接操作 | 从 REPL 所有的临时 Context 改为独立进程/私有 profile 的默认持久 Context |

## 生命周期

1. 新包环境入口创建每账号独立浏览器，保存只在本机可读的归属资料；公开 Page 原样交给 Codex。
2. 原 prepare 一次登记环境并分配账号，已就绪路径复用原结果。
3. 操作和判定由 Codex 决定。普通错误不变更调度状态；用例完成沿原保存入口同步。
4. REPL 重置连接原进程及原页面，已执行导航不重放。原页面关闭时由 Codex 观察后选择页面。
5. 实际进程退出可显式重启原 profile；旧版确实退出需换环境时在原 checkpoint 原子替换绑定，保留原账号集合和记录，不唤醒其他模块。
6. 保存回执未知暂停下一用例，读取同一 request_id 的独立回执；原 pending 写入规则保留，不自动重发或演练业务。
7. 明确结束才关闭全部归属进程、核实退出，立即沿原交还/发布/通知/ACK 完成。关闭失败或退出未知不伪造释放证据。

## 交付与边界

用户明确禁止测试：本次不执行单元、浏览器、合成故障、业务回归或付费模型验证。只做代码审查、源文件语法检查、客户端清单生成，以及标准 Jenkins DEPLOY=true 构建/启动/健康检查。

既有在途包不被热覆盖，也不向正常模块发送升级消息。后续派发使用新包；原任务明确恢复时使用原目录和记录锚点。无运行验证意味着不能声称真实多账号、断线恢复、性能或全部业务已通过。浏览器进程崩溃、权限不足、验证码、实际业务缺陷和未知提交仍需 Codex 根据现场处理，平台不会自动判通过或重放。

### 无租约且尚无接单记录的结束

原执行者已真实结束时，仍沿原 `direct_test_session(action=finish)` 提交原 task_id、node_id、holder_id 和 dispatch_id；浏览器停止事实按原参数及实际证据报告。只有派发记录而未 claim 的节点，把退出时间保存在原 dispatch_offer，不伪造接单或重新领取账号。completed 与退出确认是不同字段；最终报告仍检查实际浏览器停止、交还及当前记录修订，不能为发布跳过这些事实。
