# 项目总报告

项目总报告复用现有 `account_projects` 和会话归属。无需重新建项目或根据域名猜测归属；未绑定的会话不会自动混入。入口为「配置项目 → 项目总报告」，来源报告顶部也可进入所属项目总报告。UI、API、需求分析、压测报告保留各自来源；只有结构化功能用例进入用例统计。

## 自动更新与资源隔离

- 使用独立单线程后台投影，每 3 秒检查文件指纹。通过进程文件锁保证一个数据目录只有一个汇总工作者；不使用测试执行器，不调用模型或业务服务。
- 首次读取来源报告；后续只解析新增或变更的报告及更正文件，未变更内容从分片缓存读取。发生变化后重算项目展示投影，打开报告只读取已发布缓存。
- 项目归属、来源文件和原子保存的增量游标共同构成持久化工作意图。进程重启会恢复，不依赖内存通知。汇总前后核对指纹，源数据发生变化则不发布混合版本，下轮重试。
- 测试报告发布路径没有等待汇总。后台仍占用少量磁盘、CPU 和内存资源，不能承诺零资源开销或固定更新时间。项目投影最多 100000 条唯一用例，超限显示更新失败，保留旧版；应按项目/版本合理划分任务。
- 状态包括排队、更新中、已更新、失败。失败保留上一版且明确提示自动重试。新增报告存在短暂更新延迟，显示汇总时间；修改、提交前再次验证来源。

## 一致性与审核

用例标识包括回归来源链、原用例编号、版本、环境、目标、客户端、角色和类型。不同独立会话同名用例不会合并。版本未记录时明确标记，不能宣称当前版本通过。部分回归只覆盖对应结果，阻塞/未执行不会沿用旧通过结论。并行同时间冲突明确标记，不能择一宣布通过。

每项保存原会话、原报告、原编号、更正修订号。页面展示原编号和来源，内部复合标识只用于路由。原来源报告、操作对象与范围变化后拒绝过期更正和确认。原始证据不改写；导出包含来源列，附件引用原文件，不复制视频或截图。文件缺失不能静默生成完整下载包。历史报告即使已超出会话导航列表上限，仍按原所属会话校验并访问原报告和审核草稿，不把导航裁剪误判为证据删除。没有来源或结构化用例时明确提示不能形成测试结论。

缺陷展示保留所有明确身份及原草稿 ID；仅凭回归关联合并同一缺陷，不按标题去重。总报告复用原有 PingCode 记录、文件锁、防重复提交、未知结果核实和批量队列。队列保存审核来源指纹，真正执行前重新检查同一会话链是否已有新结果；范围变化或内容过期逐项失败，不自动重试外部业务写入。取消队列不受汇总过期校验阻碍。

多条人工确认写入各自原会话的持久化确认集合，重复确认幂等，不覆盖其他继续任务、不在汇总时启动测试。补充数据、规则确认、启动补测沿用来源报告入口；总报告不复制另一份账号或执行状态。

权限沿用已有报告协作机制：登录成员的来源报告协作、匿名公开报告只读、账号项目管理只属于项目所有者。总报告不会授予原本没有的工作空间或测试数据编辑权限。

## 存储与回退

仅新增隐藏的报告容器和 `project-total/{current.json,status.json,sources/*.json}` 派生缓存。容器通过 `aggregate_account_project_id` 指向既有业务项目，从测试会话列表和数量额度排除。项目绑定、账号、凭据、原始报告、测试任务的数据格式保持兼容。

更换归属后旧缓存立即停止作为当前报告展示；删除来源显示缺失，删除业务项目后总报告不可访问，原会话历史保持既有规则。回退经 revert MR 和 Jenkins，原会话和报告可继续使用；派生缓存可保留供重新上线恢复，无需迁移或复制业务数据。
