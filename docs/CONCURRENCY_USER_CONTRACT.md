来源：[分析多功能并行测试的影响](thread://01a13d57-bcfb-7343-879b-849f30f653c5?hostId=local)，2026-10-15 13:58:34（北京时间），turn `01a13e24-155a-7700-b805-ea080ab56aca`。

> 我的设计这个池的初衷就是提前并发把所有探索任务执行完，所以探索是要共享账号的，不同于执行池的区别是，执行池必须一号一任务

> 一个探索池的号，其他的都是执行池的号，任务数大于执行池的账号数量时，任务直接先抢占完执行池的号，就是探索和执行直接一条龙，多出的任务就进入探索池共享一个号去探索测试用例，然后所有任务探索完成之后，由最后一个任务持有这个号直接进行执行池，继续执行任务，其他探索完的任务就等待执行池空闲。但这里有一个场景探索池没号了，中间插进来新任务，如何进行探索？

更早同一聊天，turn `01a13de8-dab2-73a0-8420-e485e8a599a6`：

> 用例设计我说的不是黑盒设计，我说的是探索性的。测试用例会分两部分先探索然后设计测试用例，然后后续会操作中补充。

因此必须保留的主流程是：

1. 系统安排账号用途，用户只配置项目账号，不手工选择探索池／执行池或填写内部策略。
2. 能拿到空闲执行账号的任务，独占贯穿探索、设计和执行。
3. 多出的待探索任务共用探索账号，各自独立浏览器会话、用例、证据及进度，提前并发探索设计；不能全部等上一模块执行完才开始认识页面。
4. 探索完成者保存设计和证据，退出共享持有后等待独占执行资源；同一轮继续，不全量重做探索。
5. 最后探索者按已采纳的公平规则沿用原账号，平台原子完成共享转独占。不能同时存在其他共享授权和独占授权。
6. 账号不是永久固定属于某一池。探索号转走后，新的任务可用空闲执行号一条龙；多个待探索任务可由后续安全释放的账号重新组成探索池；不能共享正在独占执行的账号。

不能把“所有任务都独占”“没有共享策略所以全排独占”“只写了探索阶段字段”当成上述主流程已交付。缺少目标系统共享规则是实际未完成的接入事项，必须如实列明，不能把内部适配工作转嫁成用户配置门槛，也不能编造已核验证据直接放行未知共享操作。
