## 两条执行链路

新任务（网页开始、MCP、免安装客户端）默认 `local_browser`，含义为**当前聊天是执行 Codex**，浏览器通过已有执行连接无窗口运行。历史名称保留以兼容调用方，不表示复制用户 Chrome 登录态。

1. 只有连接、查询或读资料不启动任务。给出测试目标后登记原会话与范围；新建请求使用稳定 request_id，响应丢失按同 ID 查回执。
2. `direct_test_session claim` 在原控制器登记当前聊天 holder_id，进入同一账号队列。没有当前聊天领取不占号，也不启动另一个 Codex。无资源时可继续不依赖资源的材料准备。
3. 领取返回 lease_id。浏览器执行机启动无界面上下文并 ACK。当前 Codex 用 context 读取目标、原证据、Skill 和已分配账号；credentials 仅取当前独占账号，用 browser 自己登录和操作。
4. browser 的 request_id 对应持久化命令。result 取回原结果，响应丢失不重复点击；未知结果先读页面核实，用 reconcile 记下依据。账号密码不写入聊天、报告或日志。
5. record/cases/assets 等仍使用原具体用例、增量记录和真实证据规则。checkpoint 保留进度。需要人工时 wait 保留浏览器，在当前聊天说明具体待办；收到用户回答后 continue。
6. finish 让原浏览器退出；执行机确认进程退出后交还账号。查询 finish 可得到实际回收结果。正常完成、阻塞及停止均生成最终报告，未知结果不伪装通过。原 finish_test_workflow 入口也接入直接任务交还。

后台执行保留为显式 `managed` 路线：平台分配，执行机启动后台 Codex 并取账号登录。已有任务不自动换执行者。后台双向消息和收到确认尚未作为已交付能力，普通新任务不默认进入这条路线；没有用它替代当前聊天沟通。

两条路线共用 orchestration.sqlite3 中的账号租约。旧的外部浏览器 coordinate_ui_resources 接口保留兼容，但不自动将一个不受执行机管理的外部浏览器当成可强制回收的浏览器。新直接流程不使用这套独立占号文件。

## 并发与资源

- 删除本机每 2 GiB 一个模型额度的估算；当前聊天不占后台模型额度，也没有“只能一个 Codex 会话”的平台限制。
- `--max-models=0` 默认不附加模型固定上限；运营者明确配置远端服务额度时仍可设置。`--max-browsers=0` 默认由浏览器/机器资源计算，保留显式配置。
- 浏览器初始估算仍为 768 MiB/份；运行后根据本执行机浏览器进程 RSS 的观测峰值调整，可用内存与 CPU 忙碌状况限制新增浏览器。该初始值不是实测结论，不承诺任意机器能开几十个浏览器。
- 调度分别计算浏览器占用和后台推理占用；直接聊天仅需浏览器资源与账号。按项目轮转，同项目保持队列顺序；业务资源 locks 参与互斥。
- 当前 Codex 可为下一业务阶段显式请求多个 account_ids，平台一次性分配完整集合，不凑齐不占一部分账号。账号不足继续排队，不能借另一任务的账号。实际浏览器份数按集合大小扣除。
- 子任务支持继续拆分与显式依赖，保存原目标与观察，检查依赖不存在及成环。共享前置的原 fixture 消费者接口接入两条执行路线；不自动删除业务对象。

## 超时、回执与恢复

| 场景 | 当前处理 |
| --- | --- |
| 从未送达的派发超时 | 持久化事件证明未交给执行机，取消事件并回收占用；保留阻塞原因与最终报告 |
| 已送达但启动没有 ACK | 120 秒超时撤权，等待原执行机结束并确认浏览器/进程退出；不重复创建执行者 |
| 主机在线但任务无进展 | 600 秒独立进展超时；普通状态查询不算进展；撤权、结束、回收，原任务阻塞等待核实续接 |
| 主机失联 | 服务端 60 秒阈值撤权；执行机本地 40 秒阈值开始中断。网络调用本身有超时，因此阈值不是端到端硬时限 |
| 等待人工 | 保留浏览器与原因，当前聊天沟通；1800 秒超时结束为阻塞，不伪装完成 |
| 主机重启 | 日志识别旧任务；按 PID 与进程创建时间停止原任务浏览器，避免 PID 复用误杀；回收后不自动重跑未知业务 |
| 交还回执丢失 | 原交还请求幂等重传，原业务不重放；回收后重复 finish 可查已回收回执 |
| 业务提交回执丢失 | 同节点稳定操作 ID 只执行一次；pending/unknown 不重发，允许只读核实，保存 confirmed/not_sent 依据后继续 |
| 永久失联且无法证明旧执行已结束 | 明确隔离，账号不冒充空闲。必须恢复原执行机并完成退出确认；不能承诺任意网络分区下同时安全强抢账号和绝不重复业务 |

派发与命令事实由事务持久化；定时调度进程使用文件锁单活。备份恢复后的完整跨机对账演练不包含在本轮验证中，不能宣称已验收灾备切换。

## 报告与验收范围

原始用例、历史失败和未验证检查点保留。任务结果与覆盖完整度分开。资源先释放，报告失败不重跑业务；新结束任务的报告生成可独立重试。直接路线以任务交还为最终判定，旧外部直接会话以明确结束标记判定；中间保存不推送，最终结果指纹不会被中间报告回执去重。

验收使用隔离临时数据、模拟时钟与本机 HTTP 固定页面，不使用被测项目，不调用付费模型，不写 PingCode，也不向真实企业微信群发送验收消息。包含 MCP HTTP 默认入口、双路线同池并发、主机心跳与任务进度分离、多账号原子领取、重复命令、未知结果核实、启动/进展/失联超时、原线程之外的浏览器进程恢复回收、人工等待、原任务续接及阻塞最终报告。

没有将后台完整双向沟通、远端模型限流压力实测、永久离线主机的物理隔离、备份恢复演练标为通过。共享探索不在当前独占分配主路径重新开启；用户要求删除的预登录核验、身份审批、网络策略审批和阶段交接门槛不恢复。
