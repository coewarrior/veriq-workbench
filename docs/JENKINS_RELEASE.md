## 0.16.36：历史回执按条存储，保持原执行协议

一次操作原来反复读取、解析并重写同一条全量 JSON；历史截图/页面回执会拖慢当前动作、
心跳和调度，并通过 SQLite 写锁相互阻塞。此次只调整存储访问，未调整并发容量、FIFO、
租约、登录、账号回收或未知业务操作的防重放规则。主机认证移出异步事件循环。

首次启动在一个 SQLite `BEGIN IMMEDIATE` 事务内将原 `state` 表重命名为
`state_v1_backup`（完整原始快照，不删除），拆分为 `state_metadata` 和 `state_history`。
后者按 `(kind,key)` 存操作/命令，正文回执独立于状态字段，使用时才加载；事务只写改变的行。
迁移失败整体回滚；版本不兼容时拒绝迁移。启动仍由既有 Jenkins 排空、切换、健康检查管理。
数据只留在原受限数据卷，不导出凭据、业务证据或备份到 Git/构建日志。

保留 `state(id,value)` 兼容视图及旧版本启动 INSERT/整条 UPDATE 的触发器，旧镜像
自动回滚后仍能读取**包括升级后产生的回执**的当前数据、正常启动并写入；恢复旧镜像性能也会回到旧路径。
不能用迁移时快照覆盖正在运行的数据，否则会丢掉升级后的记录。若确需人工恢复原始物理格式，
