# API 与 UI 共用工作台

`/api-testing` 与 `/ui-testing` 使用同一份 `index.html`、`app.js` 和公共样式。
会话列表、删除与恢复、Codex 授权、连接码刷新、执行进度、报告历史与 PingCode 提交沿用现有实现。
`ui-workflow.js` 只提供 UI 的资料表单、任务要求、浏览器执行说明和任务消息。

## UI 流程

1. 保存会话名称、目标页面和测试要求。
2. 在「准备用例」核对或修改本轮目标。
3. 点击「交给 Codex 完成任务」，复制公共授权弹窗中的消息。浏览器测试仍由 Codex 执行，网页不会自行启动浏览器。
4. 执行进度自动同步，报告发布后进入报告步骤。报告内继续使用原有缺陷审核及 PingCode 提交流程。

已有执行结果可从第一步导入 XLSX，直接进入报告。导入会话不会要求重新生成用例或执行 HTTP 测试。

## 共享报告审核

API 执行报告、任务报告和 UI 导入报告使用同一份浅色双栏界面：左侧筛选缺陷，右侧审核正文和截图；全部用例与原始证据单独切换。阻塞、跳过和未执行不计入已执行进度。

提交沿用原有 PingCode 接口、来源标识和历史记录。已提交与结果待核对项不可再次选择；读取状态失败时禁止批量提交。正文按原有章节编辑，API 请求及依据不会被替换为 UI 模板。单条和批量审核复用当前页草稿，切换缺陷保留正文与截图；刷新页面不保留未提交编辑。

新界面在打开在线报告时加载，历史链接可直接使用；冻结 HTML、打印证据和原始 JSON 保留。2026-10-12 按用户要求调整为任意已登录账号可共同修改报告；匿名继续只读，提交入口仍要求登录。具体状态及协作边界见 [报告协作](REPORT_COLLABORATION.md)。用例设计报告与压测报告沿用各自布局。

## 兼容与边界

- 沿用已有项目、任务、报告存储结构，不迁移历史数据。
- bootstrap 默认返回 API 会话，`?test_kind=ui` 返回 UI 会话。共享删除和回收站返回值在前端按当前类型筛选，避免操作后混入另一类型的会话。
- 已有 `/api/ui-tests` 创建和导入接口保留，既有报告链接继续有效。
- UI 仅在目标资料与浏览器执行方式上区分；不为 UI 暴露 HTTP 用例执行、压测或接口编辑。
- 本版不新增 UI 自动脚本执行器或页面内逐条用例编辑。测试要求和结果导入保留现有能力。

## 验证

前端状态回归涵盖 UI 步骤条件、任务消息、报告历史及会话类型筛选；后端验证共享页面、类型隔离、XLSX 和原有 PingCode 报告。
本地浏览器验证新建、修改目标与授权、XLSX 导入、删除恢复、窄屏布局，以及 API 文档导入。
所有浏览器验证使用独立的本地临时数据，不创建真实 PingCode 缺陷。
