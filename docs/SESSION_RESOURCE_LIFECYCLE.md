# 会话与资源生命周期场景核对（0.17.29）

依据：2026-10-19 用户要求清理旧状态，回收站任务不能持续占用资源；推导重复 Codex 接入、停止同步和删除后项目仍不可编辑。保持原 D01–D15、BC-01–BC-11 与独立模块会话约定。以下为实现推导及代码核对，不是业务实测结果。

| 场景 | 平台处理 | 资源与历史 |
| --- | --- | --- |
| 未领取／排队／等待派发时删除 | 在会话删除事务中沿原 stop 控制，取消派发、清除预留及旧 holder | 无资源无需等待浏览器；执行者 ACK 单独记录 |
| 已分配但 start 从未送达 | 取消原事件，记录 undelivered_leases | 可直接回收，不伪造退出 ACK |
| 浏览器运行／共享准备／共享成员删除 | 原租约立即撤权，原执行机退出主、辅助及核验浏览器后交还 | 不抢占其他模块账号，不更改探索公平与并发容量 |
| 只删除模块记录 | 停止对应节点及其子节点 | 同任务其他模块仍按原控制意图推进 |
| 全任务停止，子节点没有租约 | 子节点停止，汇总容器按真实子节点终态结束 | “结束”不表示用例通过 |
| 在途操作中停止 | 取消尚未交付的命令；已发送请求保留实际回执 | 未知结果不重放、不假定服务端已撤销 |
| 已隔离／已退出但资源保留 | 保持 isolated/retained，不退回假 stopping | 账号待核实与浏览器容量分别计量 |
| 删除已保留的浏览器现场 | 请求原主机关闭已登记的浏览器／辅助进程，确认后归还浏览器容量 | 删除会话取消继续保留运行窗口；业务未知操作和业务保留条件仍须核实，不能用浏览器关闭证明服务端安全 |
| 会话资料已回收／已彻底删除 | 原主机可读取最小收尾上下文，不再因读报告目录失败卡住交还 | 不创建替代会话、不恢复被删文件；原调度证据保留 |
| 旧版遗留回收站／孤儿节点 | 原调度周期自动核对目录、停止并去除预留；已结束无租约的旧 holder 清理 | 不修改其他用户的有效任务，不重跑业务 |
| 恢复回收站 | 恢复资料；保留 stop 意图 | 须明确继续，重连和领取都不能当作恢复授权 |
| 永久删除时资源仍在收尾／未知 | 暂拒绝销毁证据，回收站显示占用及原因 | 确认退出、核实后可删；不可用删除绕过归还条件 |
| 同模块另一 Codex 领取 | 原 holder 占用时不重新分配；同 holder 更换已登记 executor_ref 也拒绝 | 可以查询进度；不同模块各用独立会话。holder/ref 是协议身份，不冒称平台验证了桌面进程身份 |
| 停止后旧派发迟到 | received/offered 派发均取消；旧 dispatch_id 无效 | 新派发仍沿原协调与接单协议，不继承旧权限 |
| 主机断线／进程退出不明 | 原 40 秒本机撤权、60 秒服务端失联与既有恢复逻辑保留 | 不因超时直接把账号变为空闲 |
| 发布排空期间停止 | 网页／MCP stop、pause 和会话删除仍可进入原鉴权控制 | 不放行 resume、新 claim 或新业务轮次 |
| 回收站任务收尾／报告失败 | 延后报告生成，不反复读取已删除目录，不发送旧报告 | 保存原证据，报告是否生成不决定资源是否释放 |
| 项目改地址／解绑账号 | 根据实际节点和租约判断；completed/blocked/stopped 且无租约不占项目锁 | 管理任务状态优先于旧 mcp_progress 文案；真实在途、未知或保留资源仍说明具体模块与原因 |

同步边界：控制事务提交即拒绝新的受控操作；原执行机通过现有 3 秒心跳接收撤权，耗时还包含网络和实际关闭过程。工具内等待同一回执，保留已确认提速，不增加模型逐步轮询。平台不能强制终止外部 Codex 聊天的推理；协调者仍须中断模块聊天并提供执行者退出 ACK。浏览器退出、账号释放、本地收到 ACK 分别展示，不能互相替代。

验证：本次只做语法、完整差异审查、标准 Jenkins 构建和启动健康检查；未运行业务测试、付费模型、额外回归或性能测试。线上旧状态修复及版本确认以实际发布记录为准。

### 已核销隔离的自动收尾（0.17.30）

`reconcile` 或原执行机迟到的确定回执只核实原动作，不代表用例通过。既有调度周期补偿检查所有 hold，经 `resource_holds.releasable` 核对原证据、主辅助通道退出和无保留条件，按 `return_account` 的 resolved 幂等回执释放。归还事务再次检查，原主机下一次心跳获得实际释放更新并落盘 ACK；隔离 ACK 与释放 ACK 继续分开。未核实操作、缺失记录、在途命令、现场保留或退出不完整不会被自动核销。停止／暂停意图优先，资源释放不自动恢复被停止的测试。

旧节点上的“等待原执行进程退出”不会覆盖已确认退出事实。保留最初的隔离操作集合与原因，同时展示当前剩余核实项和等待原因。此修复只随后续发布生效，本次没有改写当前线上隔离或执行状态。
