# PostgreSQL 持久化与短事务迁移

用户最新修订：SQLite 不适用于测试平台。本任务撤销未合并的 SQLite 行存储方案，改为平台独立 PostgreSQL；不使用现有业务数据库。仍须彻底解决大状态与长写事务，保留既定调度、账号、历史结果与所有在跑测试，直接 MR/Jenkins/Gitee。

数据：section/key 元数据、node/revision 历史、task/baseline 字段分别按行持久化，保留所有字段、JSON 类型、顺序与嵌套修改；operations/direct_commands 独立正文，audit/幂等回执及登录账号/会话一并迁移。现有报告/附件文件和加密密钥不搬移、不重写。

并发：PostgreSQL MVCC 只读不抢调度写锁。控制/授予保持既有单调度原子性；明确独立的节点保存采用共享调度门及节点锁，其余节点可同时保存。写锁先于读取权威状态，避免等待期间使用旧快照；不重放含文件/外部副作用的事务，不擅自加业务重试。历史正文不进入普通调度读/写。

切换：标准 Jenkins 管理专用 PostgreSQL 容器/卷/凭据，未开放外部端口。原活动保护通过并排空、停止旧服务后才迁移；严格核对完整值/类型/顺序及数量/摘要。候选健康确认前禁止业务写入及后台调度。首次激活尚未尝试时可恢复旧服务；一旦尝试激活（包括响应丢失）禁止自动回退 SQLite，以 PostgreSQL 为唯一权威数据继续恢复。后续兼容 PostgreSQL 的镜像回滚仍须通过活动保护。旧 SQLite 仅作为只读迁移来源/迁移时备份，不覆盖上线后的数据。

保留 CONCURRENCY_USER_CONTRACT D01–D15、BEHAVIOR_CONTRACTS、总调度兜底与真实退出/ACK。无独立监视聊天、无改结果/停止当前测试、无生成与覆盖变更。测试范围仍为静态审查、独立代码评审及标准发布必需构建/启动/健康，不新增/运行额外回归或业务测试。
