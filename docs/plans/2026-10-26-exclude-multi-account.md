# 平台排除多账号业务测试

依据：用户明确要求“多账号场景全都计为不测”“肯定是改平台”，并授权改完重测一轮。

仅修订多账号业务覆盖要求：设计、计划、派发、执行与续接统一不测；不申请第二账号或等待集合。平台公共策略同时供接口、页面、任务包和随包 Skill 使用。保存具体设计与已有观察，未执行项不算通过。多个模块各用单账号并发、单账号权限/匿名覆盖、原公平队列、浏览器隔离、停止 ACK、清理责任及保存协议保持。

实施顺序：
1. 加入公共排除策略，接入页面用例计划、API 执行及资源申请/阶段选择，排除项返回明确不测原因。
2. 同步平台随包说明、MCP、任务包与行为约定；更新版本和生成产物。
3. 静态语法/完整差异审查及独立代码评审；不额外运行回归或业务测试。
4. GitLab MR 合并，标准 Jenkins DEPLOY=true 发布，核对 published、线上版本及 SHA，再同步专用 Gitee。
5. 所有上述条件具备后，新开本轮六模块重测，排除多账号；已停止旧轮保持停止，保留原报告。

验收分别记录：策略及入口一致性、标准发布凭据、Gitee SHA、实际新轮结果。上线或静态检查不等于业务测试已通过。
