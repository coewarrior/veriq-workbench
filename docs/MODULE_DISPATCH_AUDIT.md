# 当前 Codex 模块执行衔接核对（2026-10-18）

依据：原《多任务并发测试平台设计方案 v1.10》的模块任务树、叶节点领取资源，以及用户后续明确的“当前 Codex 直接执行优先、平台仅管任务/账号/回收/排队、后台需明确选择”。不恢复已被用户取消的身份预核验、恢复预算或默认后台流程。

| 环节 | 本次确认的遗漏 | 修正／保留位置 |
|---|---|---|
| 用户列出模块 | 正常入口默认只有 session 总节点；MCP 未暴露模块参数 | 两个启动工具接受 modules；返回叶子 ID、范围、依赖、状态和委派说明 |
| 网页先创建任务 | 接入后再次启动只返回总任务，不能登记初始模块 | 尚未领取且没有基线的占位节点在原 task/轮次原地拆分；相同计划重发幂等 |
| 谁派发 | “当前聊天执行”说明未区分协调者和模块执行者 | 当前 Codex 使用环境已有委派能力，协调者不占业务账号；每个执行者独立 holder/node/目录，不要求用户另开聊天 |
| 模块业务锁 | 拆分继承父锁，但忽略子模块声明的锁 | 父锁与子锁取并集，真实依赖只约束相关节点 |
| 账号和浏览器 | 原队列可分配多租约；此次没登记模块，所以没有其他模块入队 | 保留原子账号独占、FIFO、公平项目调度、实际 browser_slots；直接执行不受后台 model_slots 约束，不加新数值限制 |
| 登录／业务操作 | 已有直接执行工具 | 继续由对应 Codex 自行登录、操作 headless 浏览器；不新增后台模型或另一套浏览器 |
| 记录归属 | 已有模块独立记录，但交接只强调总会话 ID | 执行者使用 context.project.id、case_id_prefix；父聊天汇总，避免多执行者竞争同一 revision |
| 状态反馈 | 未执行前序被当成阻塞；direct record 保存未更新页面执行阶段 | 未执行保持 not_run；真实阻塞仍限制相应点；按已保存结果更新阶段，兄弟模块的设计不倒退执行阶段 |
| 保存错误 | 未告知是哪条用例／检查点／依赖 | 返回明确位置与条件，不取消真实执行条件，也不要求重跑业务 |
| 停止与回收 | 原 stop 可停止所有叶节点，退出确认后交还；交接未明确通知子执行者 | 同步各入口停止要求，保留超时、host ACK、防未知写重放；本轮已停止，不因升级恢复 |
| 后台执行 | 原路由保留，交互完整性仍是之前已披露限制 | 只有用户明确选择 managed；直接执行并行不因此转后台 |

## 验收边界与未完成事项

- 本次只做代码／语法／接口清单一致性核对和标准 Jenkins 构建、启动、健康确认。用户已停止业务测试，未重跑业务，也不声称已用业务证明模块并发。
- 平台不控制当前 Codex 环境能同时提供多少子执行者；实际委派能力不足必须说明，已有模块留在原队列，不伪称正在执行或默默改成后台。平台返回明确节点不是“子执行者已经启动”的证据。
- 已经持有租约或已有用例基线的任务不能通过新初始计划热替换。保留原记录，只有未领取占位节点走本次新增登记入口；原探索安全检查点拆分能力保留，不宣称能够自动重新切分任意历史基线。
- 停止时一批观察保存失败：结果检查点引用的前序仍为 partial，原校验拒绝整批。已有观察保存在原任务本地输出；未因这次修复编造前序通过或重测。另一次读取曾返回 HTTP 500；只读查询原 execution 的 89 条记录成功，尚无证据定位该瞬时 500 的根因，不能宣称已修复。
