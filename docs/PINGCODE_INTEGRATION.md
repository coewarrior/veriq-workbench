# PingCode 缺陷提交（0.8.1）

入口：测试台左下角「集成管理 · PingCode」，或 `/integrations/pingcode`。
在线报告中，失败/执行异常/清理异常及文档检查发现旁显示「提交到 PingCode」。
点击后人工核对、编辑中文标题和描述，选择项目、缺陷类型、负责人、优先级和项目字段，勾选已审核后提交。不会调用模型，不会由 MCP 自动发布。

## 自动分级与批量审核

报告中的缺陷支持自动填入优先级与严重程度，仍由人工审核。Codex 发布新报告时分别评估 `severity`（影响）和 `priority`（紧迫性）；旧报告缺少分级时按标题作保守初评。界面显示依据与不确定性，不为分级额外调用模型 API。

分级按目标项目的选项名称映射，绝不按数组顺序或猜测字段 ID。严重程度优先写入当前项目的对应可编辑单选字段；没有可匹配字段时写入缺陷描述。有多个同级选项或无法匹配时，留待人工选择，不伪造选项。优先级和严重程度可分别修改。

报告顶部提供「全选可提交缺陷 / 批量审核并推送」，每条问题旁也有复选框。审核窗口显示逐条标题、描述、分级；可统一设置项目、类型、负责人、其他项目字段，也可统一调整分级。修改任何内容都会取消审核勾选。

勾选审核后逐条提交，逐条显示成功、失败或待核对。成功项和结果未知项不会再次进入提交队列，只有明确失败项可修正并重新审核。支持停止后续提交；正在发送的请求等待结果后停止。关闭页面时服务端保留已发起项的提交记录，刷新后可以继续剩余项。批量复用单条的来源校验、人工审核、持久化和文件锁保护，不是全有或全无的事务。

## 授权与配置

支持应用 Client ID / Client Secret（按官方接口获取企业令牌）或已有 Access Token。
应用凭据来自 PingCode 企业后台的凭据管理。当前接口需要读取项目、工作项配置并创建工作项的权限；公有云文档对应 scopes `pcp:read:pjm:project`、`pcp:read:pjm:workitem`、`pcp:write:pjm:workitem`。企业令牌不代表当前网页用户实名，应用数据范围应限制到允许的项目。

默认 API 基础地址 `https://open.pingcode.com`；当前版本选 `pjm`，旧版部署选 `project`。基础地址不要带 `/v1/pjm`。先保存并读取项目，再保存默认项目与缺陷类型。读取成功仅证明读权限，创建权限需真实提交时验证。接口版本由管理员根据部署版本选择，不在创建失败后自动改接口重试。

个人配置按浏览器会话隔离，凭据用现有主密钥 Fernet 加密落盘；页面不回显。更换地址、授权方式或 Client ID 时清除旧凭据，必须重新填写。

管理员如需全员共用，可在容器持久卷中放置仅管理员可读的配置文件（0600），并设置 `PINGCODE_CONFIG_FILE=/data/pingcode-shared.json`。文件结构：

```json
{
  "base_url": "https://open.pingcode.com",
  "api_version": "pjm",
  "auth_mode": "client_credentials",
  "client_id": "在服务器填写",
  "client_secret": "在服务器填写",
  "default_project_id": "目标项目 ID",
  "default_type_id": "缺陷类型 ID"
}
```

共享文件属于服务器机密配置，不能加入源码、发到聊天或放在静态目录。网页不能修改共享配置；个人配置可覆盖自己的连接，清除个人配置后回到共享连接。当前没有独立的管理员登录系统，因此不能把共享配置写入权限开放给所有内网用户。

私有部署的 HTTP 或内网地址：在服务器 `.env` 设置 `PINGCODE_ALLOWED_ORIGINS=https://pingcode.internal`（具体 origin，可逗号分隔），重建容器。只信任管理员明确允许的地址。连接固定 DNS 解析结果、禁止跳转和代理、验证 TLS，不会因网页传入地址而开放其他内网访问。

## 记录与异常恢复

提交记录存储在会话项目的 `pingcode/` 下，不修改冻结用例、结果 JSON 和报告 HTML。
在线读取报告时注入同源提交控件，已有报告刷新即可使用；离线文件继续支持查看和复制描述，不直接联网提交。

记录以「运行/分析报告 ID + 缺陷草稿 ID」确定；草稿序号来自不可变的该份报告，不跨运行自动合并。提交前持久化 pending，使用文件锁避免多进程/多次点击重复创建。创建成功保存工作项 ID、显示编号、官方 html_url、审核后的内容快照和浏览器会话标识。没有实名登录，因此该标识不能被当作实名审核记录。

明确的 4xx 拒绝允许修正后重新审核。超时、断连、5xx、成功响应缺少工作项 ID，以及发送后服务重启均视为结果待核对，不自动重发。
恢复方式：输入已有工作项 ID，服务端读取并核对项目、标题和正文后关联；历史记录兼容原来源标识。也可人工在 PingCode 核查后选择「已人工核对未创建」，再重新审核提交。新提交的正文不追加审核分级或内部来源标识。

缺陷正文使用审核后的问题描述，优先级和严重程度写入工作项属性，来源关联保存在平台内部。单条缺陷审核窗口支持直接粘贴系统截图，不需要先保存本地文件；页面预览后，提交时由服务端上传到对应 PingCode 工作项并把经过类型与大小校验的图片内容以 data URI 嵌入缺陷正文，不使用会过期的附件下载地址。单张上限 5 MB，每条最多 3 张，支持 PNG、JPEG 和 WebP。工作项创建成功但截图写入失败时不会重复创建缺陷，页面会明确提示到 PingCode 核对截图。

只读报告链接不能代替缺陷正文，免登录查看页也不会提供 PingCode 提交入口。当前不做 PingCode 状态双向同步、不接每人 OAuth 登录；复杂自定义字段可填写官方要求的 JSON 值，远端校验错误会返回到审核窗口。

## 正文容量与失败补交

正文（含 HTML 与图片预览）在发送前校验 65,536 字符上限。截图超出剩余容量时生成 WebP 预览，原始图片完整保留在工作项附件中，正文预览不依赖临时签名链接。正文自身过长时在创建前提示精简，不截断用户内容。

已创建但正文或截图失败的记录显示“重试正文与截图”。重试只更新原工作项并回读核验，复用已上传附件；失败输入与已上传附件进度持久保存。旧记录从原报告快照恢复截图。远端正文被他人修改时停止覆盖并提示核对。

## 批量验收、重新打开与选择状态

缺陷审核支持「待验收」「待重新打开」「同步异常」快捷筛选；全选只选择当前筛选结果，搜索或切换筛选会清空选择。勾选同类缺陷时直接显示验收、重新打开或提交按钮；其他处理、同步维护和人工更正通过自定义菜单进入。验收与重新打开更新原单，回归结论仍保留；人工更正结论、拒绝和暂缓必须填写依据。

批量确认冻结对象与版本，列出可执行及排除项。成功、无需变更和明确排除的记录取消勾选；明确失败、停止后未执行的记录保留勾选。响应不确定的记录取消勾选并进入核对，不能盲目重复写入。结果摘要与逐条结果保留在列表上方，支持重新审核失败项。标题修改与提交也遵循相同的成功取消选择规则。

远端验收/重新打开先读取当前状态，写入后回读；未知结果持久化，通过「刷新同步状态」核对后再处理。重复点击同一操作不会重复执行已完成的状态变更；同一原单存在相互矛盾的回归结论时，批量操作会阻止该条并提示核对。同步状态与回归结果分开展示，外部同步失败不改变测试结论。
