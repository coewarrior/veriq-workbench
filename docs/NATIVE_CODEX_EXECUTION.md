## 路线与不变项

默认：平台提供任务、分配账号及已有结果 → 各模块独立桌面 Codex 读取现有 Skill → 持久 `cua` JavaScript 环境直接操作浏览器 → 已知步骤连续执行并独立判定 → 每条完成立即同步结果。平台不代理点击、输入、读取或等待，不重新引入逐动作检查、动作队列或回执轮询。

账号分配及交还、结果/证据同步、S1 停止为平台职责。旧 Runner 与后台任务继续保留其兼容协议，不能将新默认直接迁移到正在执行的旧任务。用户已进一步允许原生探索共享账号，仅由 Skill 约束操作，并接受不再逐请求拦截的剩余风险。平台仍管理共享成员、退出及转独占；共享成员需要写入或进入执行阶段时申请独占，不逐动作核验。浏览器隔离、自动唤醒能力仍按真实接入说明，不宣称沿用了旧 Runner 拦截。

## 浏览器接入的实际边界

本实现只复用当前 Codex 原生工具已经能够连接的浏览器，不新增远端 CDP 接入，不提供任意服务器 Chromium 自动接入桌面 `cua` 的能力。平台分配账号并不表示浏览器已经打开、登录完成或获得了独立 Cookie 环境；这些事实仍来自实际浏览器工具。

多账号并行须使用当前原生工具支持的独立登录上下文，例如实际独立的浏览器 profile 或上下文，并在取得该上下文时完成对应登录。Chrome 同一 profile 下新建多个 tab 仍共享 Cookie 和登录态，不能当作账号隔离；不同 Codex 聊天也不自动产生独立登录环境。平台不导出/注入 Cookie，不凭会话或标签数量宣称隔离已经实现。当前工具没有所需上下文能力时如实列明能力缺口，不擅自引入 Runner、CDP 代理或另一套控制服务。

以上是接入能力事实，仅在实际选用或切换登录上下文时处理，不新增逐动作身份核验、账号查询或远程检查。

## 2026-10-20 隐藏页面默认与持久交接修复（0.17.40）

本次补齐新原生页面的隐藏默认和账号交还后的协调通知链路。新页面使用 `cua.createBrowserTab('iab', url, {visible:false})`，工具失败不能移除隐藏参数或自动回退到可见 Chrome；旧在途任务继续原路线和资源归属，不迁移。隐藏只控制显示，不隔离 Cookie 或登录态；多账号仍需当前工具实际提供的独立上下文，不能抢用、退出或覆盖另一任务的登录态。

资源真实交还后，原 `direct_test_session(action="finish")` 返回持久 `handoff`。有效 `pending` 包含 `message_tool=send_message_to_thread` 和 `message_arguments={threadId,prompt}`；执行者沿原授权在生命周期边界调用一次现有消息工具，明确成功后用原 `finish` 补记 `arguments.handoff_notification={event_id,thread_id,sent:true}`。响应未知时保留待通知事实，不自动重发，不把本地文件或账号释放当作送达。

协调者收到后沿原 `direct_test_session(action="dispatch")` 以 `arguments.handoff_ack={task_id,node_id,event_id}` 消费，可不传 `modules`。消费和随后执行者 `claim` 成功获得账号分别保存；继续原节点、派发、顺位、依赖及范围，不重建任务或重跑已有结果。普通未绑定协调者的单模块不制造事件；有派发但没有真实协调会话绑定时为 `unbound`，不伪造目标。没有账号仍保存续测位置并结束回合，不轮询、不定时唤醒；已停止任务不因资源交接恢复。
